# INTERACTION-013：ProTable 查询表单选择器失效

## 1. 文档状态

- 阶段：问题分析与修复方案。
- 结论：已定位为旧 ProTable CSS/测试选择器与当前 QueryFilter DOM 不一致；**本阶段未修改源码**。
- 影响：完整 Ubuntu 回归中 `horizontal table search labels align with their controls` 稳定失败，同时全局查询表单对齐样式可能未实际生效。

## 2. 问题描述

导航回归进入 `/admin/customers` 后，页面、客户查询输入框和查询按钮均已正常渲染，但测试查找 `.ant-pro-table-search` 时得不到元素，随后无法取得 label/control 的 bounding box。

该失败不是页面冷启动：失败快照中客户管理页面及查询表单已经完整出现。实际问题是测试和全局 CSS 都仍引用 `.ant-pro-table-search`，而当前 `@ant-design/pro-form` 的 QueryFilter 使用 `.ant-pro-query-filter`。

## 3. 根本原因

### 3.1 第三方内部类名发生漂移，测试仍使用旧类

当前依赖实现通过 `getPrefixCls('pro-query-filter')` 生成 QueryFilter 根类，因此默认类名是 `.ant-pro-query-filter`。`navigation.spec.ts` 仍使用 `.ant-pro-table-search`，locator 永远为空。

### 3.2 全局对齐样式也指向不存在的类

`index.css` 中查询区背景/间距和 label 垂直对齐规则都以 `.ant-pro-table-search` 为前缀，当前客户页面不会命中。也就是说，即使删除失败测试，产品样式规范仍可能没有应用到所有 ProTable 查询区。

### 3.3 项目内部已有正确选择器但未统一

`governance.css` 和 `investigate.css` 已经使用 `.ant-pro-query-filter`，说明不同页面/全局样式处于两套选择器时代。当前缺少公共查询表单 hook 或统一封装，导致实现与测试分别漂移。

## 5. 详细修复步骤

### 步骤一：统一产品样式入口

1. 将全局失效选择器更新为当前 QueryFilter 根类，并限制在 `.tds-content` 或公共业务表格容器内，避免影响登录/第三方独立区域。
2. 统一查询区表头高度、label/control 垂直对齐、间距和窄屏换行策略。
3. 审核 `governance.css`、`investigate.css` 的页面级规则，明确哪些是业务特殊布局，哪些应删除或合并到全局规则，避免 specificity 互相覆盖。
4. 保留 `labelWidth='auto'` 等现有行为，不改变字段、查询参数和按钮逻辑。

### 步骤二：为 E2E 使用稳定定位方式

1. 不再把第三方私有类名作为唯一测试入口。
2. 优先通过可访问名称定位实际查询字段（如 Customer ID）和其所属表单；如果无法稳定表达，则在项目自己的查询区域容器上提供 `data-testid`/语义化 class。
3. 测试应先等待表单可见和页面 ready，再测量首个 label/control 的中心点差值。
4. 同时检查展开/收起后的 QueryFilter，防止只验证默认折叠状态。

### 步骤三：补全查询区覆盖矩阵

至少覆盖：

- 客户管理、设备管理；
- 告警、威胁、威胁情报；
- 治理/配置中使用 ProTable QueryFilter 的页面；
- 1440px 与 390px；
- 中文、英文；
- 查询区折叠、展开；
- 浏览器缩放或窄容器下没有 label/control 重叠。

### 步骤四：防止再次漂移

1. 将 QueryFilter 根定位封装为公共 E2E helper 或 app-owned hook。
2. 在依赖升级检查清单中加入“ProTable QueryFilter DOM/CSS hook”验证。
3. 通过静态搜索禁止新增 `.ant-pro-table-search`，避免旧选择器再次出现。

## 6. 潜在影响

1. 全局选择器修正后，此前未命中的样式会真正应用到所有 ProTable 查询区，可能改变间距、背景和窄屏布局，需要逐页检查。
2. `governance.css`、`investigate.css` 已有更高 specificity，合并时可能造成局部样式回退。
3. 若只改测试而不改全局 CSS，测试可以通过，但产品对齐规则仍未生效；两者必须同时处理。
4. 若测试继续依赖第三方内部 class，未来 Pro Components 升级仍会复发。

## 7. 验证方法

1. 运行 `navigation.spec.ts` 的查询标签对齐用例，确认能定位真实表单并取得非空 bounding box。
2. 在 1440px 下 label/control 中心点误差不超过既有 2px 标准。
3. 在 390px 下允许响应式纵向布局，但 label、输入框和操作按钮不得裁切、重叠或超出页面。
4. 中英文分别验证客户、设备、告警、威胁情报、治理页面。
5. 检查 QueryFilter 展开/收起、查询、重置、分页和排序功能不变。
6. 静态搜索确认项目源码和 E2E 中不再残留 `.ant-pro-table-search`。

## 8. 验收标准

- 查询表单样式规则命中当前真实 DOM。
- E2E 不再依赖过期第三方类名，且能真实验证标签与控件对齐。
- 所有 ProTable 查询区在中英文、桌面/窄屏下无裁切、重叠和错误换行。
- 查询、重置、分页、排序及权限行为保持不变。
