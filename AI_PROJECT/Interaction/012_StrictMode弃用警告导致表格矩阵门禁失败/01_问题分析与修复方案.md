# INTERACTION-012：StrictMode 弃用警告导致表格矩阵门禁失败

## 1. 文档状态

- 阶段：问题分析与修复方案。
- 结论：已定位到 React StrictMode 与 Ant Design/Pro Components 依赖链产生的 `findDOMNode` 弃用告警；**本阶段未修改源码**。
- 影响：Ubuntu 完整 4-worker 回归 44 个失败中有 28 个由该问题直接造成。

## 2. 问题描述

`table-layout.spec.ts` 已成功完成表格数量、数据行、布局、溢出、对比度、页面横向滚动和 API mock 检查，但在测试末尾统一检查 `consoleErrors` 时失败。

失败消息主要为：

- `Warning: findDOMNode is deprecated and will be removed in the next major release...`
- `Warning: findDOMNode is deprecated in StrictMode... DomWrapper4`

调用栈反复出现 `SingleObserver`、`ResizeObserver`、`Tooltip`、`DensityIcon`、`ToolbarRender`、`ProTable` 等 Ant/Pro 内部组件。28 个失败覆盖不同语言、主题、视口以及告警详情、威胁情报、订阅源、客户和设备相关表格，表现高度一致。

这不是 Playwright 1.59.1 新增的浏览器故障，也不是表格对齐修复回退；本轮首次在真实 Ubuntu 浏览器完整执行表格矩阵，才把既有开发模式控制台告警暴露为门禁失败。

## 3. 根本原因

### 3.1 React StrictMode 正确暴露了旧式 DOM 查找

应用入口明确使用 `React.StrictMode`。依赖链中的 ResizeObserver/Tooltip/ProTable 工具栏仍有路径通过 `findDOMNode` 获取 DOM 节点。React 18.3.1 在 StrictMode 下将其输出为 `console.error`。

当前锁定版本为：

- `@ant-design/pro-components` 2.8.10；
- `@ant-design/pro-table` 3.21.0；
- `antd` 5.27.6；
- `rc-resize-observer` 1.4.3；
- `react-dom` 18.3.1。

### 3.2 控制台门禁只允许另一类 antd 告警

`table-layout.spec.ts` 的 allowlist 仅允许 `/Warning: \[antd: ...\]/`。`findDOMNode` 是 React StrictMode 消息，不符合该表达式，因此每个触发该依赖路径的表格 surface 都会在最后的 `expect(errors.consoleErrors).toEqual([])` 失败。

### 3.3 不能把问题简单处理为“忽略控制台错误”

控制台门禁用于发现运行时异常和可访问性/组件兼容风险。若宽泛忽略 `findDOMNode` 或全部 `console.error`，将掩盖应用自身错误。需要先区分：

1. 应用自定义 Tooltip/ResizeObserver 子节点没有转发 ref；
2. Ant/Pro 依赖内部无法由应用代码直接修正的告警；
3. 某些内置 ProTable 工具按钮（例如 density/settings）单独触发告警。

## 5. 详细修复步骤

### 步骤一：建立唯一告警与触发组件清单

1. 从完整报告中按“告警正文 + 首个非 React 栈帧 + surface”去重。
2. 分别关闭/替换单个工具项进行对照运行，确认 `DensityIcon`、Tooltip、ResizeObserver 各自贡献。
3. 检查应用传给 Tooltip/Popover/ResizeObserver 的自定义 React 组件是否使用 `forwardRef`；若应用层子节点是根因，优先改为原生 `span`/`button` 包装或正确转发 ref。

### 步骤二：验证依赖升级路径

1. 在独立分支升级 Ant Design、Pro Components 及 rc 依赖到彼此兼容的锁定版本，不使用浮动安装结果直接入库。
2. 执行类型检查、生产构建、现有组件测试和完整表格矩阵。
3. 核对 ProTable 搜索、排序、分页、列设置、密度、刷新、抽屉/弹窗和主题是否保持原行为。
4. 只有在告警消失且功能/样式没有回退时，才采用依赖升级方案。

### 步骤三：对无法升级的内置工具项做最小替换

如果告警来自 ProTable 内置 density/settings Tooltip 且当前依赖版本无法修复：

1. 保留用户需要的功能；用项目自己的原生按钮/Tooltip 实现等价入口，避免触发旧式 DomWrapper。
2. 不得仅为通过测试关闭用户可见的列设置、密度或刷新能力。
3. 将替换逻辑下沉为公共表格工具栏组件，避免各页面重复实现。

### 步骤四：仅对确认的第三方开发告警设置临时精确豁免

若经过步骤一至三仍存在依赖内部、开发 StrictMode 专属且无法消除的告警，可作为临时措施：

1. allowlist 必须同时限定精确消息、已确认的依赖栈特征和允许的 surface，不能只匹配 `findDOMNode` 关键字。
2. 每次命中都写入测试 annotation 和计数，报告中可见。
3. 添加负向测试：应用自身抛出的普通 `console.error`、pageerror 以及不同栈的 `findDOMNode` 仍必须失败。
4. 建立对应技术债编号和移除条件；依赖升级后如果告警不再出现，测试应主动失败提示删除豁免。

### 步骤五：保留质量门禁

- 保留 `React.StrictMode`。
- 保留 `errors.pageErrors` 和 `errors.consoleErrors` 为空的最终检查。
- 不使用覆盖 `console.error`、关闭浏览器日志或通配 allowlist 的方式“修复”。

## 6. 潜在影响

1. 依赖升级可能改变 ProTable DOM、类名、主题 token、Tooltip portal、表格列设置和类型定义，需要完整 UI/E2E 回归。
2. 自定义替换内置工具栏会影响键盘操作、可访问名称、权限和本地化，必须保持等价。
3. 精确 allowlist 若限定不足会掩盖真正问题；若限定过严，依赖小版本改变栈文本又会造成门禁失败。
4. 去掉 StrictMode 虽可消除告警，但会同时失去副作用和旧 API 诊断，明确不采用。

## 7. 验证方法

1. 在开发模式和 Ubuntu 固定 Playwright 镜像中分别运行 `e2e/table-layout.spec.ts --workers=4`。
2. 覆盖 1440/390、en-US/zh-CN、light/dark 以及所有当前 surface。
3. 验证表格数据和布局断言仍通过，且未允许的 console/page error 为零。
4. 人工制造一个普通 `console.error`，确认测试仍失败；随后撤销该验证改动。
5. 对列设置、密度、刷新、Tooltip、抽屉和弹窗做键盘与鼠标操作验证。
6. 运行完整 E2E，确认原 28 个失败消失且没有新增 DOM/样式回归。

## 8. 验收标准

- 28 个 surface 在真实 Ubuntu 浏览器中全部通过。
- StrictMode 保留，控制台门禁保留。
- 首选结果为告警源消除；若使用临时豁免，必须满足消息、栈、surface 三重精确限定并有可见计数。
- 所有表格功能、主题、语言、响应式和可访问性行为不回退。
