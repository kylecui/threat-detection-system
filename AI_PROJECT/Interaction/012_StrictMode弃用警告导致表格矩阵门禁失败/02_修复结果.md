## 2. 告警清单与根因（步骤一）

1. **去重结果**：解析 Ubuntu 完整回归 `20261029T021345Z/results.json` 中 28 个失败收集到的全部控制台消息，按“消息 + 组件栈”去重后**只有 2 种**，28 个失败各出现 1 次：
   - `findDOMNode is deprecated…`，组件栈 `SingleObserver > ResizeObserver > Tooltip > DomWrapper > … > ListToolBar`；
   - `%s is deprecated in StrictMode … findDOMNode was passed an instance of DomWrapper`，组件栈 `ColumnHeightOutlined > DomWrapper > SingleObserver > ResizeObserver > Tooltip`。

   `ColumnHeightOutlined` 就是 ProTable 工具栏“表格密度”按钮的图标。28 个失败恰好是“每个含 ProTable 的页面 × 4 个快速档组合”（告警明细、情报指标、订阅源、客户、设备抽屉、设备数据弹窗、设备列表，共 7 个展示面）。
2. **源码定位**（本机安装的 `@ant-design/pro-table` 3.21.0）：
   - `es/components/ToolBar/index.js` 把每个工具项渲染为 `<span><Tooltip>{icon}</Tooltip></span>`。“密度”的 icon 是 `<DensityIcon/>`，而 `DensityIcon` 是 `React.memo` 包装的普通函数组件（`ToolBar/DensityIcon.js`），**不能持有 ref**。
   - antd Tooltip 内部的 ResizeObserver 判断子元素无法挂 ref，于是退回到 `DomWrapper` 类组件加 `findDOMNode`，React StrictMode 把它报告为 `console.error`。
   - “刷新”的图标 `ReloadOutlined` 和“列设置”都是可转发 ref 的组件，所以不会触发。
3. **应用层自查**：4 个 ProTable 都没有向 Tooltip、ResizeObserver 传入自定义子组件；告警完全来自 ProTable 内置的密度项，应用代码无法通过传入其他图标来修复（`options.densityIcon` 只能替换 DensityIcon 内部的图标，外层的 `Tooltip > memo 组件` 结构不变）。
4. **被去重掩盖的风险**：React 对同一组件名的 `findDOMNode` 告警只打印一次，因此修复后需要确认没有其他来源被掩盖，见 4.2 第 4 行。

## 3. 修复结果总结

1. **新增 `TableDensityControl`**（应用自有的密度控件），与内置项等价：
   - 同样的 `ColumnHeightOutlined` 图标、点击打开的下拉菜单、宽松/中等/紧凑三档、菜单宽度 80；
   - 文案通过 `useIntl()` 读取 **Pro Components 自己的** `tableToolBar.density*` 文案，中英文与原来一致；
   - Tooltip 包裹的是原生 `<button type="button">`，可以挂 ref，不再走 `findDOMNode`；
   - 改成原生按钮后，该控件还可以用键盘 Tab 聚焦、Enter 打开，并增加了 `:focus-visible` 焦点环。
2. **新增 `useProTableToolbar()` hook**，返回值展开到每个 ProTable：
   - `options: { density: false, reload: true, setting: true }`：只关闭内置密度项，刷新和列设置保持开启；
   - `optionsRender`：把自有密度控件插回原位置，**顺序仍为“刷新、密度、列设置”**；
   - `size` / `onSizeChange`：通过 ProTable 已有的受控尺寸接口生效，默认 `middle`，与原来未设置时一致。
3. **4 个 ProTable 全部接入**：告警明细、威胁情报指标、客户、设备（步骤三第 3 点：替换逻辑下沉为公共组件，不在页面中重复实现）。
4. **样式**：`.tds-table-density-control` 把按钮重置为与内置图标相同的外观（透明背景、无边框、继承颜色和字号）。前后截图对比，工具栏外观一致。
5. **控制台门禁保持严格**（步骤五）：
   - 门禁逻辑从 `table-layout.spec.ts` 提取为 `e2e/helpers/consoleGate.ts`；
   - 白名单仍只有原来的一条 antd 弃用提示，并改为以 `^Warning: [antd: …]` 开头的锚定匹配，比原来更严格；
   - **没有**为 `findDOMNode` 或 StrictMode 添加任何豁免，没有覆盖 `console.error`，也没有移除 StrictMode。
6. **依赖升级（步骤二）**：未执行。原因：
   - 本工作区无法访问 npm 仓库；
   - 根因已在应用层消除，不再需要通过升级来去掉告警；
   - 升级 antd 或 Pro Components 会带来 DOM、主题和类型方面更大的回归面。

   建议作为独立任务评估；届时可以用本问题新增的用例验证升级后内置密度项是否已修复，再决定是否退回内置实现。

## 6. 未解决问题与注意事项

1. 在 Ubuntu 镜像中复跑表格矩阵：

   ```bash
   scripts/testing/run_frontend_e2e_ubuntu.sh e2e/table-layout.spec.ts e2e/protable-toolbar.spec.ts --workers=4
   ```

   原 28 个失败应全部消失。如有新的控制台错误，门禁会直接失败并给出完整消息，请反馈给我分析，**不要加宽泛的白名单**。
2. 新增 ProTable 时必须展开 `useProTableToolbar()` 的返回值，契约测试会检查已有的 4 个。如果需要关闭某个工具项，在 hook 返回的 `options` 基础上覆盖即可，不要重新启用 `density: true`。
3. 以后升级 Pro Components 时，可以在独立分支临时恢复内置密度项，运行 `protable-toolbar.spec.ts` 和表格矩阵（开发模式）；只有确认无告警时才考虑退回内置实现。
4. 本机请执行 `npx tsc --noEmit`。新组件的类型按本机 `pro-table` 3.21.0 的类型定义编写：`options` 为 `OptionConfig`，`optionsRender` 为 `(props, defaultDom) => ReactNode[]`，`onSizeChange` 为 `(DensitySize) => void`。本环境没有 antd 类型包，无法做完整类型检查。
