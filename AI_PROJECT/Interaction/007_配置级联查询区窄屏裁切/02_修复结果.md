## 2. 修复结果总结

1. **组件作用域类名**（全部以 `.tds-config-cascading` 开头）：
   - 根节点：`.tds-config-cascading`；
   - 查询表单：`.tds-config-cascading__lock-query`；
   - 两个输入控件：`.tds-config-cascading__field-control`；
   - 操作区：`.tds-config-cascading__lock-actions`。
2. **移除关键几何的行内样式**：
   - 实体类型 `Select`、实体 ID `Input` 的 `style={{ width: 180 }}` 改由作用域类控制；
   - 表单的 `style={{ marginBottom: 16 }}` 移入样式文件；
   - 不换行的 `<Space>` 换成受控的 Flex/Grid 操作容器 `<div className="tds-config-cascading__lock-actions">`。
3. **断点布局**（写在 `configuration.css`，只用 CSS，不监听 `resize`）：
   - **≥ 576px（平板、桌面）**：表单为可换行的 Flex（行间距 12px，列间距 16px）；两个控件保持原来的 180px；三个按钮在操作区内可换行（间距 8px）。1440 下 5 个控件仍在同一行，与修复前一致。
   - **< 576px（手机）**：表单改为单列 Grid；标签移到控件上方并左对齐；两个控件宽 100%；三个按钮纵向排列、宽 100%、最小高度 44px（触控目标）。
4. **组件自带样式**：`ConfigCascading.tsx` 现在自行 `import './configuration.css'`（与同目录其他配置页一致），不再依赖外层页面引入。该组件没有生产入口，因此这一导入不进入任何生产页面。
5. **行为保持不变**：
   - `handleLoadLocks`、`openAddLockModal`、`handleRemoveAllLocks` 原样绑定；
   - “移除所有锁定”未选实体时仍只提示“请先选择实体”，选中实体后仍弹出危险确认；
   - 必填校验、`type="number"`、`min={1}` 不变。
6. **确认没有生产入口**（按产品决策只验证、不改动）：
   - `App.tsx` 中没有任何 `ConfigCascading` 路由或菜单；
   - 唯一引用它的 `pages/Configuration/index.tsx` 本身没有被任何文件导入；
   - 测试专用页面 `e2e/harness/config-cascading.*` 不在 `vite.config.ts` 的生产构建入口中。
   - 以上三点已写入契约测试 `test_no_production_entry`。
7. **删除豁免**：`table-layout.spec.ts` 中 `NEW-B` 登记已删除。

## 5. 与方案的差异

| 方案 | 实际 | 原因 |
| --- | --- | --- |
| 6.2.1 桌面“三段 Grid + `minmax()`” | 桌面用可换行 Flex，手机用单列 Grid | 保留 `layout="inline"` 的标签与控件排布，桌面观感与修复前完全一致；Flex 换行在 768/1024 下也能自然排布，DOM 顺序即视觉顺序 |
| 6.3.2 桌面字段“约 180–220px” | 保持 180px | 试过 200px：不改变任何宽度下的换行，但会让桌面观感与修复前不同，因此保持原值 |
| 8.2 “1024 恢复紧凑桌面布局” | 1024 英文按钮换到第二行 | 修复前同样如此（第 4.2 节第 2 行）；测试只要求两个字段同一行、三个按钮同一行，1440 才要求全部单行 |
| 8.4.5 “无权限访问用例” | 新增，使用测试专用页面 + `CUSTOMER_USER` 角色 | 组件没有生产入口，只能通过测试页面验证 |

## 6. 未解决问题与注意事项

1. 按产品决策，`ConfigCascading` 仍无生产入口。将来开放入口时，需另行做权限、文案、业务完整性和回归验收（方案 2.5），不在本问题范围内。
2. 手机端卡片高度增加（标签上置、按钮纵向排列），这是完整保留字段和按钮的预期结果。
3. 将来如果把组件挂到其他页面，注意 `configuration.css` 也会被引入；其中其他规则都以 `.tds-config-` 开头，不会影响无关页面。
