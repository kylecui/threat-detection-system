## 5. 遗留问题

### 5.1 P2：ConfigCascading 测试 Harness 导致标准 lint 门禁失败

- 位置：`frontend/e2e/harness/config-cascading.tsx:27`
- 现象：`HarnessShell` 是在入口文件中定义但未导出的 React 组件，触发：

  ```text
  react-refresh/only-export-components
  Fast refresh only works when a file has exports.
  ```

- 影响：
  - `npm run lint` 以退出码 1 结束；
  - 项目要求零 warning，因此标准 CI/发布门禁不能通过；
  - `02_修复结果.md` 把 lint 列为需要后续执行，但当前实际执行结果证明尚未完成验收。
- 根因：E2E Harness 同时承担组件定义和 `createRoot(...).render(...)` 入口职责，却没有为 Fast Refresh 规则提供可导出的组件边界。
- 整改建议：
  1. 优先将 `HarnessShell` 改为有名称的导出组件，例如 `export function HarnessShell()`，继续在同文件渲染；
  2. 如果规则仍不接受入口文件结构，则把组件移到独立文件并由入口文件导入；
  3. 只有在确认 Harness 不参与 Fast Refresh 后，才考虑对 `e2e/harness/*.tsx` 增加最小范围 ESLint override，不得全局关闭规则；
  4. 重新执行 `npm run lint`，必须达到 0 warning、退出码 0。
- 是否阻断验收：**是**。原方案明确要求执行 lint，且当前失败文件正是该问题的测试入口。
