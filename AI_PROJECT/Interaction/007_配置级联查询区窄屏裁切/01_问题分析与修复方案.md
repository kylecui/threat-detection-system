# 007 配置级联查询区窄屏裁切——问题分析与修复方案

## 1. 文档信息

- 问题编号：`INTERACTION-007`
- 优先级：P2
- 来源：`INTERACTION-004` 全局表格 E2E 覆盖补齐后发现的新增响应式问题（测试中登记为 `NEW-B`）
- 当前阶段：仅分析与制定修复方案，未修改业务源码、样式、路由或测试
- 影响组件：`ConfigCascading` 配置级联管理中的“锁定管理”查询与操作区
- 已确认产品决策：**保留 `ConfigCascading` 代码，但暂时不开放生产入口**

## 2. 修复边界与产品决策

本问题后续需要修复源码，但不改变 `ConfigCascading` 当前的产品可见性：

1. 保留组件、服务调用、权限控制和测试入口，便于后续继续开发及验证。
2. 不在生产导航、`App.tsx` 正式路由或用户可见入口中新增该页面。
3. 不因暂不开放生产入口而删除组件，也不能以“用户暂时看不到”为理由保留已知布局缺陷。
4. 若 E2E 使用专用测试挂载页，应明确它是测试入口，不得被生产菜单或普通用户访问路径引用。
5. 本文不讨论何时正式上线；未来开放入口必须另行进行权限、文案、业务完整性和回归验收。

## 3. 问题描述

在 390px 英文环境中，配置级联“锁定管理”卡片的查询区总宽度超过内容容器，右侧操作按钮被裁切。已知测试测得：

- 查询区内容约 425px；
- 可用内容容器约 375px；
- 三个英文按钮的组合宽度约 395px，且当前容器不允许换行；
- 外层 `.tds-content` 使用 `overflow-x: hidden`，因此超出的部分不是形成可用的局部滚动，而是直接不可见。

预期结果：桌面端保持紧凑横向布局；手机端查询字段和三个操作按钮按可用宽度自然堆叠或换行，文字完整、按钮可点击、校验提示可见，不产生页面级横向滚动或裁切。

## 4. 根本原因

### 4.1 内联表单没有移动端布局策略

`frontend/src/pages/Configuration/ConfigCascading.tsx:535` 使用 `Form layout="inline"`。内联表单适合桌面横向排列，但组件没有为小屏设置列布局或换行规则。

### 4.2 两个控件使用固定 180px 宽度

- `frontend/src/pages/Configuration/ConfigCascading.tsx:541-547`：实体类型 `Select` 固定 `width: 180`；
- `frontend/src/pages/Configuration/ConfigCascading.tsx:549-555`：实体 ID `Input` 固定 `width: 180`。

固定宽度与标签、表单间距、校验信息叠加后，无法适应窄屏。

### 4.3 三个文本按钮放在禁止换行的 `Space` 中

`frontend/src/pages/Configuration/ConfigCascading.tsx:556-568` 使用普通 `<Space>` 包裹“加载”“添加锁定”“移除所有锁定”。`Space` 默认不会自动把长按钮组变成稳定的移动端列布局。英文 `Remove All Locks` 明显增加组合宽度。

### 4.4 外层隐藏横向溢出，使问题表现为裁切

`frontend/src/index.css:894-900` 的 `.tds-content` 设置 `overflow-x: hidden`。这是应用壳层避免页面整体左右晃动的合理策略，但它要求内部业务组件自行响应式重排。当前表单没有重排，最终被壳层裁切。

### 4.5 现有配置页响应式样式没有覆盖该遗留组件

`frontend/src/pages/Configuration/configuration.css` 已包含部分配置页面断点规则，但 `ConfigCascading` 没有使用对应作用域结构，也没有自己的移动端类名。其 JSX 主要依赖行内样式，难以通过现有设计体系统一调整。

## 6. 详细修复步骤

### 6.1 建立组件作用域，不修改应用壳层

1. 给组件根节点、锁定查询表单、字段区和操作区增加语义化类名，例如：
   - `.tds-config-cascading`
   - `.tds-config-cascading__lock-query`
   - `.tds-config-cascading__lock-actions`
2. 在配置页面样式文件或组件专用样式文件中实现响应式规则，避免继续增加关键几何行内样式。
3. 保留 `.tds-content { overflow-x: hidden; }`；不能通过允许整个应用横向滚动来掩盖本地布局错误。

### 6.2 用 CSS Grid/Flex 建立明确的断点布局

1. 桌面端可采用三段布局：实体类型、实体 ID、操作区；字段使用 `minmax()`，操作区使用剩余空间并保持合理间距。
2. 平板端允许字段与操作区换行，但需保持 DOM 顺序与键盘 Tab 顺序一致。
3. 390px 手机端改为单列：两个字段宽度 100%，操作按钮建议纵向排列并占满可用宽度，避免英文文案再次触发临界换行。
4. 不通过监听 `resize` 或反复读取 DOM 宽度来决定排列；使用 CSS 媒体查询和原生布局能力。

### 6.3 移除固定控件宽度对移动端的限制

1. 将 `Select` 和 `Input` 的 `style={{ width: 180 }}` 迁移为作用域类控制。
2. 桌面端保留约 180–220px 的合理字段宽度；移动端使用 `width: 100%` 和 `min-width: 0`。
3. 确认必填校验文案显示后，表单项不会重新撑宽或与下一行重叠。
4. 保持输入类型、最小值、校验规则和表单实例不变。

### 6.4 重构操作按钮容器，但不改变行为

1. 将无换行 `<Space>` 替换为受控的 Flex/Grid 操作容器；若保留 `Space`，至少使用 `wrap` 并通过作用域样式保证 390px 下稳定，但 CSS Grid 单列更可预测。
2. 保留三个按钮的现有文案、图标、类型和点击处理函数：`handleLoadLocks`、`openAddLockModal`、`handleRemoveAllLocks`。
3. “移除所有锁定”继续保持危险操作视觉和原有确认/保护流程，不能因布局调整而绕过确认。
4. 移动端按钮点击目标建议至少 44px 高，焦点轮廓清晰，禁用与加载状态可辨识。

### 6.5 保持表格局部滚动与生产入口策略

1. 锁定列表的 `tableLayout="fixed"` 与 `scroll={{ x: 728 }}` 属于表格自己的宽度策略，本问题不应删除。
2. 查询表单修复后，页面级容器无横向溢出；表格在窄屏仍仅在自身区域横向滚动。
3. 不把 `ConfigCascading` 加入生产菜单或正式路由。
4. 保留管理员门禁 `isAdmin`；测试入口也必须验证无权限用户不能访问业务内容。

### 6.6 清理已知问题豁免

1. 修复完成后删除 `frontend/e2e/table-layout.spec.ts:89-96` 中的 `NEW-B` 豁免。
2. 不得以缩短真实英文文案、隐藏按钮、降低字号或裁切文本使测试通过。
3. 对查询区和表格分别做溢出断言，确保查询区不溢出且表格仍能局部滚动。

## 7. 潜在影响与规避方式

- 移动端卡片高度会增加，这是完整保留字段和操作的合理结果；需避免首屏高度变化影响其他卡片，但不能因此压缩按钮。
- 从 `Form layout="inline"` 迁移到受控布局可能改变 `Form.Item` 的底部间距和校验提示位置；需要对校验失败状态单独截图回归。
- 操作按钮改为纵向后，快速连续操作仍应遵守原有 loading/disabled 逻辑，避免重复提交。
- 修改公共配置页 CSS 选择器过宽可能影响其他配置页面；所有新增规则必须以 `.tds-config-cascading` 开头。
- 当前组件未开放生产入口，因此浏览器 E2E 可能依赖测试挂载页；测试入口必须继续可用，但不能被误当成生产上线。
- 本问题不改变接口、权限模型、配置继承业务、锁定记录结构或表格数据。

## 8. 验证方法与验收标准

### 8.1 静态检查

1. `npm.cmd run lint`
2. `npx.cmd tsc --noEmit`
3. 搜索确认锁定查询区不再存在两个无条件 `width: 180` 和不受控按钮 `<Space>`。
4. 搜索生产路由与导航，确认未新增 `ConfigCascading` 用户入口。

### 8.2 响应式验证

| 视口 | 语言 | 预期 |
| --- | --- | --- |
| 390px | `en-US` | 两个字段和三个按钮完整可见；无裁切、重叠和页面级横向滚动 |
| 390px | `zh-CN` | 控件占满可用宽度；校验信息和按钮文字完整 |
| 768px | 中英文 | 字段和操作区自然换行或分栏；视觉顺序与 DOM 顺序一致 |
| 1024px / 1440px | 中英文 | 恢复紧凑桌面布局；不出现过大空白或松散按钮间距 |

### 8.3 功能验证

- 非管理员仍只看到禁止访问提示。
- 管理员可选择实体类型、输入实体 ID、加载锁定、添加锁定、移除全部锁定。
- 必填校验、数字最小值、加载态、禁用态、错误提示和危险操作确认保持原行为。
- 表格分页、固定布局、局部横向滚动和操作列不受影响。
- 键盘可按视觉顺序访问字段与三个按钮，焦点样式清晰。

### 8.4 自动化验收

1. 删除 `NEW-B` 后运行表格布局 E2E 矩阵。
2. 断言 `.tds-content` 与其内部主容器 `scrollWidth <= clientWidth`。
3. 单独断言锁定查询区每个按钮的边界均在卡片可见区域内。
4. 验证表格横向滚动发生在表格容器，不扩大页面根节点。
5. 增加或保留无权限访问用例，证明响应式重构没有绕过门禁。

## 9. 本阶段结论

根因是桌面内联表单、固定 180px 控件与不换行文本按钮组叠加，外层 `overflow-x: hidden` 进一步把超出内容裁掉。修复应在 `ConfigCascading` 内建立作用域响应式布局，不改应用壳层，也不删除表格自己的局部滚动。根据已确认决策，组件代码保留并修复，但暂时不得新增生产入口。当前仅形成方案，尚未修改源码、路由或测试。
