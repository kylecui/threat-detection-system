## 2. 修复结果总结

按方案 5.2 首选方案，把配置级联的文字按钮全部改成项目已有的 40px 图标按钮 `TableActionButton`。操作列宽度和 `scroll.x` 同步收紧：

| 表格 | 操作列（前 → 后） | `scroll.x`（前 → 后） |
| --- | ---: | ---: |
| 锁定规则（编辑、删除，2 个） | 220 → **108** | 840 → **728** |
| 实体分组（编辑、管理成员、批量分配、删除，4 个） | 560 → **200** | 1516 → **1156** |
| 成员弹窗（移除成员，1 个） | 180 → **72** | 600 → **492** |

- **每张表保留一个业务列不设固定宽度**：锁定表“配置类型”、分组表“描述”、成员表“实体 ID”。浏览器验证发现，当容器比 `scroll.x` 宽时（如 1440 下表格区域约 1335px），antd 的固定布局会把多出的宽度按比例分给**所有**定宽列，操作列因此从 108/200/72 被拉宽到 198/231/124。在 CSS 固定布局中，未定宽的列会吸收全部剩余宽度，所以现在操作列在任何宽度下都恰好等于预算值，多出的空间全部给了业务字段。窄屏时这一列至少获得 `scroll.x − 其他列之和` 的宽度：配置类型 200px、描述 240px、实体 ID 120px，与原定宽相同。
- 新增 `components/tableActionWidth.ts` 公共宽度预算：1/2/3/4 个按钮分别为 72/108/152/200px。推导公式为 `40n + 4(n-1) + 24`，单按钮不低于 72px（保证表头“操作/Actions”一行放得下）；4 个按钮按公式是 196px，沿用项目既有的 200px（与告警中心一致，给焦点环留余量）。
- 每个图标按钮都用已有翻译键作为 `aria-label` 和 `title`：`common.edit`、`common.delete`、`configCascading.manageMembers`、`configCascading.batchAssign`、`configCascading.removeMember`。中英文都不为空。
- 原有处理函数原样保留：`openEditLockModal`、`handleRemoveLock`、`openEditGroupModal`、`loadMembers`、`openBatchAssignModal`、`handleDeleteGroup`、`handleRemoveMember`。删除、移除的 `Modal.confirm` 二次确认仍在处理函数内部，未受影响。
- 关于方案 5.1 的前置决策：`ConfigCascading` 仍然没有生产路由，本轮**没有新增生产路由**。浏览器验证通过一个测试专用页面完成（`frontend/e2e/harness/config-cascading.*`，详见 004 修复结果）。保留还是退役该组件，仍需产品确认，见第 6 节。

## 5. 与方案的差异

| 方案 | 实际 | 原因 |
| --- | --- | --- |
| “增加公共操作列宽度常量或函数，覆盖 1/2/3/4 个按钮对应 72/108/152/200” | 已新增 `tableActionWidth.ts`，4 按钮按公式为 196，取既有 200 | 方案表格与告警中心现值均为 200；常量中写明了推导和取整理由 |
| 浏览器测试“通过组件级/测试专用入口验证，不新增生产路由” | 新增测试专用页面 `e2e/harness/config-cascading.html` | 只由 Vite 开发服务器提供；生产构建入口只有 `index.html`，镜像只拷贝 `dist/`，因此不会进入生产包 |
| 其他页面是否改用宽度常量 | 只在配置级联使用常量，其他页面保留数值 | 契约测试已按预算集合约束全部操作列；为不扩大改动面，未批量替换其他页面的数值 |
