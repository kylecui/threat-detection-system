# 006 设备数据流弹窗窄屏内容溢出——问题分析与修复方案

## 1. 文档信息

- 问题编号：`INTERACTION-006`
- 优先级：P2
- 来源：`INTERACTION-004` 全局表格 E2E 覆盖补齐后发现的新增响应式问题（测试中登记为 `NEW-A`）
- 当前阶段：仅分析与制定修复方案，未修改业务源码、样式或测试
- 影响页面：客户与设备 → 设备列表 → 数据状态弹窗
- 影响范围：手机宽度 390px（中英文均复现）；平板宽度 768px（英文复现）

## 2. 问题描述

打开“设备数据状态”弹窗后，桌面端显示正常，但在窄屏下，弹窗正文中的设备摘要区域宽度超过可见区域。测试证据显示：

- 390px 视口下，弹窗正文可见宽度约 332px，而内部摘要内容宽度达到约 877px；
- 768px 视口下，较长的英文标签仍会触发横向溢出；
- 页面已有的 `overflow-x: hidden` 或弹窗滚动约束只会遮住超出部分，不能使被裁切的信息恢复可见；
- 弹窗下方事件表格本身允许独立横向滚动，真正的首要问题是事件表格上方的 `Descriptions` 摘要保持了桌面三列结构。

预期结果：弹窗桌面尺寸和业务内容保持不变；设备摘要在手机、平板和桌面上分别采用适合可用宽度的列数，所有标签和值都能读到，事件表格继续只在自身区域内滚动，页面根节点和弹窗正文不产生非预期横向溢出。

## 3. 根本原因

### 3.1 描述列表列数被固定为桌面三列

`frontend/src/pages/CustomersAndDevices/index.tsx:1298-1303` 中，设备摘要使用：

```tsx
<Descriptions
  className="tds-detail-descriptions"
  bordered
  size="small"
  column={3}
>
```

`column={3}` 在所有视口都生效。Ant Design 的弹窗会随视口缩小，但内部描述表仍按三列计算固有宽度，导致弹窗已经收窄而摘要表没有同步重排。

### 3.2 跨列规则同样假定始终存在三列

- `frontend/src/pages/CustomersAndDevices/index.tsx:1305-1307`：描述字段固定 `span={2}`；
- `frontend/src/pages/CustomersAndDevices/index.tsx:1354-1362`：最后威胁分析和心跳判定规则固定 `span={3}`。

这些数值跨度只适合三列桌面布局。列数在移动端调整后，如果跨度仍写死，容易形成无效布局、空白格或继续撑宽。

### 3.3 公共详情样式禁止标签换行，但没有该弹窗的响应式例外

`frontend/src/index.css:1518-1525` 对所有 `.tds-detail-descriptions` 设置：

- 标签 `white-space: nowrap`；
- 内容允许 `overflow-wrap: anywhere`。

值可以断行，但标签不能断行。英文标签如 `Discovered Hosts`、`Last Threat Assessment` 会显著增加每一列的最小宽度。当前仅告警详情在 `frontend/src/index.css:1528-1546` 有单独的标签宽度和 480px 响应式规则，设备数据弹窗没有对应的作用域样式。

### 3.4 外层滚动限制掩盖了内容布局错误

`frontend/src/index.css:1452-1455` 为 Modal/Drawer 正文设置 `overscroll-behavior: contain`。这项设置用于阻止滚动穿透是合理的，但不会修复内部固有宽度。若再通过 `overflow-x: hidden` 隐藏问题，会直接造成信息不可见。

## 5. 详细修复步骤

### 5.1 保持弹窗职责和桌面尺寸不变

1. 保留 `Modal width={960}`，不通过扩大、缩小或改为全屏来回避内部布局问题。
2. 保留当前 z-index、关闭按钮、数据加载、状态计算和事件表格逻辑。
3. 不把整个弹窗正文强制设为横向滚动；只有数据表格可以在必要时进行局部横向滚动。

### 5.2 让摘要列数随断点变化

1. 将固定 `column={3}` 改为 Ant Design 支持的响应式列配置。
2. 建议目标：手机 1 列、平板 2 列、宽桌面 3 列；最终断点以 390px、768px、1024px 和 1440px 实测结果为准。
3. 确保 768px 英文环境实际落到两列，不能仅按中文标签长度判断。
4. 不使用 JavaScript 持续测量 DOM 宽度；优先用组件断点配置和 CSS 布局，减少重排与窗口缩放抖动。

### 5.3 解除固定数字跨度对列数的依赖

1. 将“最后威胁分析”和“心跳判定规则”等整行字段改为“占满当前行”的语义跨度；如果当前 Ant Design 版本支持 `span="filled"`，优先采用该能力。
2. 若组件版本或类型不支持 `filled`，使用与响应式列数一致的跨度配置，不能继续无条件写死 `span={3}`。
3. “描述”字段应在桌面保持合理宽度，但在一列/两列布局下自然占满可用行，不产生空白占位。
4. 验证数据为空、长描述、长时间字符串和长心跳规则时均不会把摘要再次撑宽。

### 5.4 增加设备数据弹窗的作用域样式

1. 为该 `Descriptions` 增加专用类，例如 `.tds-device-flow-descriptions`，不要直接放宽所有 `.tds-detail-descriptions`。
2. 保留内容单元格的 `min-width: 0` 和 `overflow-wrap: anywhere`。
3. 首先依赖响应式列数解决固有宽度；若 390px 英文标签仍超宽，再仅在该弹窗的小屏作用域内允许标签正常换行或适当收紧内边距。
4. 不对重要标签使用无提示省略号；若最终必须截断，应提供可访问的完整文本提示。
5. 保持标签和值的垂直对齐、颜色、字号和边框与现有详情视觉体系一致。

### 5.5 清理已知问题豁免并补充断言

1. 修复完成后删除 `frontend/e2e/table-layout.spec.ts:72-88` 中两条 `NEW-A` 豁免。
2. 让原有几何审计在 390px 中英文和 768px 英文下直接通过，而不是换一种错误信息继续加入白名单。
3. 增加针对弹窗正文的断言：`scrollWidth <= clientWidth`；事件表格的横向滚动只能发生在表格容器内部。
4. 检查摘要每个标签和值仍存在于可见 DOM，不能以 `display: none`、裁切或删除字段换取测试通过。

## 6. 潜在影响与规避方式

- 手机端摘要会从横向三列改为纵向一列，弹窗内容高度增加；应允许弹窗正文纵向滚动，并保持页底关闭按钮可操作。
- 英文标签允许换行后个别行会变高；这是保留完整信息的合理结果，但要避免标签和值视觉错位。
- 改动跨列方式可能影响桌面字段排列；应对照当前 1440px 页面，确保桌面仍为三列且长说明独占整行。
- 若直接修改公共 `.tds-detail-descriptions`，可能影响告警详情和其他抽屉；因此必须使用设备弹窗专用类控制差异。
- 事件表格本来就可能需要横向滚动，不能把“弹窗正文无溢出”错误理解为取消表格自身的滚动能力。
- 本问题不涉及 API、权限、设备状态计算、后端数据或弹窗层级。

## 7. 验证方法与验收标准

### 7.1 静态与类型检查

1. `npm.cmd run lint`
2. `npx.cmd tsc --noEmit`
3. 确认不存在固定 `column={3}` 与无条件 `span={3}` 的移动端冲突。
4. 确认新增样式只作用于设备数据弹窗。

### 7.2 响应式矩阵

至少验证：

| 视口 | 语言 | 预期 |
| --- | --- | --- |
| 390px | `zh-CN` | 摘要一列；正文无横向溢出；所有字段可读 |
| 390px | `en-US` | 长标签不裁切；正文无横向溢出 |
| 768px | `en-US` | 摘要至多两列；不再触发已知溢出 |
| 1024px | 中英文 | 布局稳定；弹窗和页面根节点无非预期溢出 |
| 1440px | 中英文 | 保持桌面三列与当前信息密度 |

### 7.3 功能回归

- 从设备列表正常打开、关闭弹窗；快速切换不同设备时摘要与事件数据正确更新。
- 状态标签、时间、主机数、威胁分析时间、心跳说明均完整显示。
- 事件表格排序、分页或滚动能力不受影响。
- 键盘焦点可进入弹窗并返回触发按钮；关闭按钮在移动端可见、可操作。
- 页面滚动不穿透弹窗，弹窗内部纵向滚动自然。

### 7.4 自动化验收

1. 运行表格/弹窗布局 E2E 矩阵。
2. 删除 `NEW-A` 后测试必须通过，不允许保留或新增等价豁免。
3. 对弹窗正文、描述表和事件表分别检查几何范围，避免只检查最外层元素。

## 8. 本阶段结论

根因是设备摘要固定使用桌面三列及数字跨度，并叠加了英文标签不换行规则；不是弹窗 `960px` 目标宽度，也不是事件表格本身。建议通过响应式列数、占满当前行的跨度语义和设备弹窗作用域样式完成修复。当前仅形成方案，尚未修改源码或声明问题已修复。
