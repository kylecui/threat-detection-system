## 2. 修复结果总结

1. **列数随断点变化**：`column={3}` 改为 `DEVICE_FLOW_COLUMNS = { xs: 1, sm: 1, md: 2, lg: 3, xl: 3, xxl: 3 }`。
   - 手机（< 768px）1 列，平板（768–991px）2 列，桌面（≥ 992px）3 列。
   - 用 antd 自带的响应式列数，不监听 `resize`，不测量 DOM。
   - 断点按实测确定：768 英文必须落到 2 列；1024 原本就不溢出，保持 3 列。
2. **跨列不再假定三列**：
   - “最后威胁分析”“心跳判定规则”由 `span={3}` 改为 `span="filled"`（占满当前行剩余空间）。
   - “描述”由 `span={2}` 改为 `DEVICE_FLOW_DESCRIPTION_SPAN`（1 列时 1、2 列及以上时 2），任何列数下都不会超出一行。
   - 已核对本机安装的 antd 5.27.6 类型定义（`es/descriptions/Item.d.ts`）：`span` 接受 `number | 'filled' | { [断点]?: number }`；`column` 接受数字或断点对象。lockfile 锁定 5.27.6。
3. **桌面布局保持不变**：antd 遇到 `span` 超出当前行剩余格数时，会把它截成剩余格数。所以原来“最后威胁分析”在 3 列下实际就是填满第 4 行剩下的 1 格（并在开发模式下打印跨列警告）。`span="filled"` 得到完全相同的排布，同时去掉了这个警告。“心跳判定规则”仍独占整行。
4. **设备弹窗专用小屏样式**（`index.css`）：
   - 摘要增加专用类 `.tds-device-flow-descriptions`，规则只作用于此弹窗，且只在 `max-width: 575px` 生效。
   - 标签列占 40%，允许正常换行（`white-space: normal; overflow-wrap: break-word`），左右内边距收紧到 10px。
   - 原因：改成 1 列后，390 英文下内容仍有 351px，超出正文可视宽 332px。来源是不换行的长英文标签（如 “Last Threat Assessment”）。按方案 5.4.3，只在此弹窗小屏作用域放开换行。
   - 公共 `.tds-detail-descriptions` 标签不换行规则不变，告警详情等其他界面不受影响。
   - 没有使用省略号，也没有隐藏任何字段。
5. **删除豁免**：`table-layout.spec.ts` 中两条 `NEW-A` 登记已删除；原有几何审计在 390 中英文、768 英文下直接通过。

## 5. 与方案的差异

| 方案 | 实际 | 原因 |
| --- | --- | --- |
| 5.3.1 整行字段“优先 `span="filled"`” | 两个整行字段用 `filled`；“描述”用断点对象跨度 | “描述”在桌面需要跨 2 格而不是占满一行（否则同一行的“发现主机数”会被挤到下一行），断点对象既保留桌面排布，又保证 1 列时不超出 |
| 5.4.3 “若 390 英文标签仍超宽再放开换行” | 已放开（仅此弹窗、仅 < 576px） | 实测仍超出 19px（351 > 332），见 4.2 第 2 行 |
| 7.2 “1024px 布局稳定” | 1024 仍为 3 列 | 1024 在修复前就未溢出（弹窗 960 宽），保持原信息密度；已纳入 7 个组合的断言 |

## 6. 未解决问题与注意事项

1. 手机端摘要变为单列后，弹窗正文明显变高（12 行）。正文可纵向滚动，页脚关闭按钮已验证可达。这是保留完整信息的预期结果。
2. 断点基于**视口**宽度（antd `Descriptions` 的响应式列数按屏幕断点计算），不是弹窗自身宽度。弹窗当前桌面宽度固定 960，两者一致；若以后改变弹窗宽度，需要重新核对 `DEVICE_FLOW_COLUMNS`。
