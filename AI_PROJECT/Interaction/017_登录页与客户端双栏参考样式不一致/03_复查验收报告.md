## 5. 遗留问题与整改建议

### 5.1 [P2，阻断通过] 主提交按钮 hover 白字对比度不足

**位置**：

- `frontend/src/pages/Login/index.tsx:33-60`，尤其第 37 行的 `colorPrimary`。
- `frontend/e2e/login.spec.ts:276-315` 的颜色检查及现有交互回归没有检查主按钮 hover 对比度。

**复现方法**：

1. 打开 `/login`，等待 bootstrap 检查结束。
2. 读取 `.tds-login__submit button` 的背景色、文字色、字号。
3. 鼠标移入该按钮，等待 CSS 过渡结束，再次读取计算样式。
4. 使用 WCAG 相对亮度公式计算文字与按钮背景的对比度。

**真实 Chromium 测量**：

| 状态 | 背景 | 文字 | 字号/字重 | 对比度 |
| --- | --- | --- | --- | --- |
| 正常 | `rgb(8, 127, 156)` / `#087f9c` | `#ffffff` | 14px / 600 | **4.6397:1** |
| hover | `rgb(35, 146, 168)` / `#2392a8` | `#ffffff` | 14px / 600 | **3.6532:1** |

14px 文字即使字重为 600，也不属于可使用 3:1 阈值的大字号文字。WCAG 2.2 1.4.3 要求普通文字至少 4.5:1，其官方说明明确包括 hover 和键盘焦点状态下的文字：[W3C Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

**根因**：登录局部主题只指定正常主色，未指定 `colorPrimaryHover`。Ant Design 从主色推导出更亮的 hover 背景，配合白字导致对比不足。独立读取当前依赖实际 Token 得到同一个 `#2392a8`，与浏览器计算样式一致。

**影响**：普通登录和首次创建管理员共用该主按钮样式，两个入口都受影响。主体配色方向正确，但悬停后文字可读性下降，与方案“校验文字及状态对比度”的要求不符。

**建议整改**：

1. 仅在 `loginTheme` 中明确设置足够深的 `colorPrimaryHover`，保持本次蓝青方向；同步核对 active/focus 及加载后的文字状态。
2. 不能只更换正常主色后假定派生状态都合格；在真实浏览器中检查最终计算颜色。
3. 补充 normal/hover/focus/active 文字对比检查，至少使所有启用状态下的普通文字达到 4.5:1；禁用态按其对应规范单独处理。
4. 分别验证“登录”和长英文创建按钮，不通过改黑白主题偏好或改变全局工作台 Token 来处理此问题。

**证据**：`evidence/03-review/independent-browser-probe.json` 中 `desktop-zh` 的 idle/hover 字段。

### 5.2 [P3，非阻断改进项] 长按空格导致密码显隐反复切换

**位置**：

- `frontend/src/pages/Login/index.tsx:133-140`，`onKeyDown` 中直接调用 `button.click()`。
- 同一渲染函数用于密码和确认密码：第 279、313 行。
- `frontend/e2e/login.spec.ts:557-566` 只覆盖两次独立的空格按键，没有覆盖自动重复。

**复现方法**：

1. 在登录或首次创建表单中输入测试密码，用 Tab 聚焦密码显隐按钮。
2. 按下并持续按住空格，触发系统重复 keydown，然后松开。

本次实际通过 Playwright 连续执行两次 `keyboard.down('Space')`，再执行一次 `keyboard.up('Space')`，浏览器记录的事件为：

```text
keydown repeat=false
keydown repeat=true
keyup   repeat=false
```

密码和确认密码两个输入框的类型均为：

```text
password → text → password → password
初始       首次按下  自动重复     松开后
```

整个过程中按钮焦点保持，密码内容长度没有变化。说明现有修复解决了焦点移回输入框的问题，但每个重复 keydown 仍然触发一次显隐切换；增加重复次数又会继续翻转，松开后的状态取决于重复次数。

**根因**：自定义空格 keydown 处理没有检查 `event.repeat`，并在 keydown 而非一次完整激活动作中调用 click。这是本次新增键盘处理带来的边界问题。

**建议整改**：在保留 Ant Design 事件兼容、键盘焦点和阻止空格进入密码框的前提下，使一次空格长按只触发一次切换，例如屏蔽重复 keydown，或按原生按钮语义调整激活时机。补“按下、重复、释放”和两次独立按键两组验证，同时确认密码值、焦点、`aria-pressed` 和动态名称保持一致。

该问题不影响普通点击登录或单次按键，按 P3 记录为非阻断改进项；本次总体不通过的阻断依据为第 5.1 节。

**证据**：`evidence/03-review/space-repeat.json`，包含两个字段的状态序列和浏览器实际 repeat 标记。
