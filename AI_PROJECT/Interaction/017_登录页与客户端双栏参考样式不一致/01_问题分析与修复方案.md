## 3. 根本原因

### 3.1 历史需求与最新要求不同

`AI_PROJECT/REQUIREMENTS.md:3-10` 的 `REQ-029` 明确要求“不采用待合并分支的双栏登录界面”，并把“桌面最大宽度 400px 的居中单卡片”作为实施方向。

`AI_PROJECT/records/changes/2026-10-26-frontend-workspace-merge-3.1.37.md:5-10` 同样记录了这一决定。当前页面和外观测试都在落实这个旧需求。

因此，本次主要是登录视觉方向需要按最新参考重新调整。现有证据不支持将其归因于安装失败、接口异常或 CSS 文件未加载。本次截图要求应作为新的视觉要求记录，取代旧需求中的单卡片限制；旧变更记录应保留以供追溯。

### 3.2 DOM 和卡片尺寸共同限制了版式

`frontend/src/pages/Login/index.tsx:93-113` 直接将品牌 header 和表单 panel 顺序放入单卡片，品牌内容是横向图标加小标题，没有独立的左栏容器。

`frontend/src/index.css:1643-1659` 将整张卡片限制为 400px，并对整张卡片统一内边距、对品牌 header 设置底部分隔线。仅修改背景颜色或卡片宽度，无法形成参考图的独立品牌区、表单区和比例关系，必须同时调整展示结构与对应 CSS。

### 3.3 登录配色同时受固定色和全局主题影响

页面背景、图标、主按钮用了登录专属固定色；卡片和文字又依赖 `--surface-color`、`--text-color` 等全局变量。`ThemeContext.tsx:13-38` 会根据本地主题或系统偏好设置 `html[data-theme]`，而 `index.css:1728-1737` 还包含登录输入框的深色覆盖。

此外，`App.tsx:915-917` 的应用 `ConfigProvider` 属于业务布局，公开的 `/login` 路由在 `App.tsx:1240` 单独渲染，并不处于该业务主题容器内。下一阶段不能假定修改业务工作台 Token 就能统一登录组件。

如果只把登录背景改浅而不处理局部文字、输入框和状态组件，保留的深色偏好可能产生浅背景、深色输入框或文字对比不协调的组合。

### 3.4 现有测试仍固定旧视觉目标，状态覆盖不足

`frontend/e2e/login.spec.ts:146-164` 明确断言 1440px 桌面视口下 `.tds-login__card` 宽度不超过 401px。任何符合本次双栏目标的大卡片都会与此断言冲突。

现有用例验证了基本登录和部分首次创建校验，但没有覆盖“新双栏 + 全部条件提示 + 中英文 + 短屏”的布局组合。`responsive-layout.spec.ts` 主要覆盖设备数据弹窗和配置级联，`i18n.spec.ts` 主要覆盖工作台语言切换，不能把它们当作登录页已经完成响应式/双语验收的证据。

## 5. 建议修复方案与执行顺序

### 步骤 1：固定本次视觉目标和功能边界

以本次截图的“浅灰背景 + 浅蓝品牌左栏 + 白色登录右栏 + 蓝青色主按钮”为方向。保留“威胁检测系统”“云原生威胁检测平台”等本平台真实文案；不因为截图写着“网络安全控制面”而重命名平台，也不照搬其他项目的账号、接口或角色逻辑。

下一阶段在研发记录中追加新要求，关联 `REQ-029` 和本问题编号。不要改写历史文件来掩盖旧方案。

### 步骤 2：重组卡片内部结构，保留真实表单

1. 保留 `<main className="tds-login">` 及其 `data-app-ready`、`data-route-path` 属性，维持 `aria-labelledby` 对应关系。
2. `.tds-login__card` 改为品牌区与表单区组成的整体卡片；原 `Form` 和事件处理继续使用。
3. 品牌区承载现有安全图标、产品名称及真实说明，表单区保留“登录 / 创建管理员并登录”动态标题。
4. 不新增产品能力宣传、默认账号提示、注册入口、记住密码或第三方登录等现有系统没有的功能。
5. 装饰圆环置于不影响排版的独立图层，`aria-hidden` 且不接收指针事件；层级低于输入框和按钮。截图底部短线若保留，只作为静态装饰，不伪装为可点击轮播控件。

### 步骤 3：按参考比例统一尺寸、文字和配色

以下是待实施的起始设计参数，并非已从客户端源码验证的精确 CSS。截图中的卡片约为 755×460 个图像像素；浏览器缩放/截图缩放未知，不能直接认定这些就是 CSS 像素。

| 项目 | 建议起始规则 |
| --- | --- |
| 桌面卡片 | 最大宽度约 760–800 CSS px，居中；先按参考图体量校准，不扩成全屏双栏 |
| 栏比例 | 约 53% / 47%；用弹性 Grid，子项设置 `min-width: 0` |
| 普通登录高度 | 约 460px 的起始最小高度，允许内容增长；禁止将整张卡片锁死为固定高度 |
| 表单栏 | 水平 padding 约 36–40px；输入框与主按钮等宽，字段和标题左对齐 |
| 字号 | 品牌标题约 28–32px，登录标题约 22px，表单/说明 14–16px；中英文分别检查 |
| 控件 | 输入框和按钮约 40–44px 高，小屏点击区域至少 44px；不直接复制截图中可能因缩放而显小的文字 |

对用户名、密码、显示名称、确认密码增加可见字段标签，并维持可访问名称唯一；使用 `Form.Item label` 建立标签关联，避免另加一个与实际输入框不关联的装饰 label。新增占位文字与标签含义区分，不能以占位文字代替字段名。

当前 CSS 同时给 `.ant-input` 和 `.ant-input-affix-wrapper` 设置 `min-height: 42px`。调整时应核对 Ant Design 包装层与内部 input 的最终高度，避免外层 padding 与内层最小高度叠加；这属于待验证风险，不是本阶段已经复现的控件高度故障。

### 步骤 4：为登录入口建立局部浅色主题

建议登录入口保持截图式浅色，登录后继续使用用户原有工作台主题：

1. 配色变量限制在 `.tds-login` 内，设置合适的局部 `color-scheme`；不要修改全局 `:root` 色板。
2. 删除或协调现有 `html[data-theme="dark"] .tds-login__panel ...` 旧覆盖，防止其继续压过新输入框样式。
3. 如需要统一 Ant Design 的 label、输入框、按钮、焦点、校验和禁用色，在登录页局部使用现有 `ConfigProvider`，配置浅色算法和登录专属 Token；使用项目已有依赖，不新增组件库。
4. 不调用主题切换方法，不覆盖 `localStorage.tds-theme`；分别验证存储值为 light、dark 及系统深色偏好三种入口。
5. 主题容器不能导致原 `main` 属性或原静态就绪合同失效；优先保留既有根节点结构与属性。

### 步骤 5：统一所有状态和响应式策略

| 状态/场景 | 必须保留及适配的内容 |
| --- | --- |
| 正常登录 | 用户名、密码、密码显隐、回车提交、成功/失败反馈 |
| Bootstrap 检查中 | 原加载反馈与禁止正常提交的按钮状态；不显示误导性的初始化结论 |
| 检查失败 | 平台暂不可用提示、重试按钮、禁用提交；重试后按真实状态更新 |
| 首次创建管理员 | 说明、可选显示名称、用户名、密码、确认密码和动态按钮；卡片随内容自然增高 |
| 会话过期 | 保留现有重新登录提示，不能恢复用户已要求去掉的“已清除会话和数据范围”内部文案 |
| 错误/多条提示 | 表单校验、平台提示和会话提示允许正常换行，不能盖住下一字段或提交按钮 |
| 窄屏/短屏 | 约 768px 以下改为上方紧凑品牌区、下方表单；页面可纵向滚动，所有控件可达 |

桌面保留双栏，断点附近也应验证表单栏最小可用宽度；手机不挤成两列、不省略字段、不通过 `overflow: hidden` 掩盖横向溢出。装饰裁切可以位于独立装饰容器，表单所在容器不能因此裁掉焦点环、错误提示或按钮。

保留既有 `prefers-reduced-motion` 规则。参考页主要依赖布局和配色，不需要新增持续动画；如有进入反馈，使用轻量 opacity/transform，不能在输入框获得焦点或提交时缩放整个卡片。

### 步骤 6：修订冲突的外观测试并补关键验证

保留现有用户名/密码校验、8–16 位首次创建密码规则、认证存储和跳转测试。将旧 `<=401px` 外观断言改为针对新目标的几何验证：

- 桌面卡片整体居中，品牌在左、表单在右，栏目不重叠；卡片、表单宽度和比例在设计范围内。
- 手机品牌在上、表单在下，页面无横向滚动，字段和按钮均在可视容器内或可滚动到达。
- 测试检查布局关系、可达性和可见结果，不以完整 CSS 字符串一致代替实际显示检查。
- 保留 `.tds-login` 的就绪合同；不以放宽超时、增加 retry 或静默跳过掩盖失败。

## 6. 业务兼容要求与潜在影响

- 首次创建成功后继续自动登录；如创建已成功但登录失败，应继续保留现有回到普通登录模式的行为。
- 保持 token、refreshToken、用户、角色、租户/客户信息的原认证处理，以及成功后 `replace` 跳转 `/overview`。
- 保持 API 层统一错误提示，避免页面 catch 再次弹出同一错误；不顺手调整 `RouteGuard` 或登录后的跳转策略。

### 6.2 风险和应对

| 风险 | 原因 | 应对 |
| --- | --- | --- |
| 创建管理员按钮被裁掉 | 比普通登录多说明和字段，英文更长 | 高度随内容增长、短屏纵向滚动，不用绝对定位表单 |
| 深色偏好导致混搭 | 全局变量和旧深色选择器仍存在 | 登录局部浅色 Token/CSS 一并处理，不改工作台偏好 |
| 修改 CSS 影响其他表单 | 全局 `.ant-input` / `.ant-btn` 选择器范围过大 | 所有新增覆盖限定登录作用域 |
| 登录自动化回归失败 | 401px 旧断言、根节点合同或重名标题定位 | 替换过时视觉断言，保留业务名称及就绪标记 |
| 只有普通登录接近参考 | 未覆盖错误态、首次创建及英文状态 | 按第 7 节状态矩阵验证并留存证据 |
| 装饰挡住控件/产生横向滚动 | 圆环绝对定位或层级不当 | 装饰禁用指针、独立裁切，真实表单不裁切 |
| 发布文档再次描述旧界面 | 打包脚本每次重新生成旧说明 | 实施阶段同步修改说明生成源，而非只改 outputs 成品 |
