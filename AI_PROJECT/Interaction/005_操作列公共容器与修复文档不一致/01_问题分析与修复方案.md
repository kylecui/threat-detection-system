# 005 操作列公共容器与修复文档不一致——问题分析与修复方案

## 1. 文档信息

- 问题编号：`INTERACTION-005`
- 来源：`001_全局表格对齐与单行显示规范/03_复查验收报告.md` 的第四个遗留问题
- 优先级：P3
- 当前阶段：仅分析与制定方案，未修改源码或既有文档
- 问题类型：组件规范、维护一致性、验收文档准确性

## 2. 问题描述

`02_修复结果.md` 中写有“所有操作列改用 `TableActions`”以及“新增表格的操作列使用 `TableActions`”等表述。但实际代码只保证了多按钮操作不换行，并没有让每一个操作列都经过 `TableActions`。

当前页面视觉上大多仍能居中，核心功能也没有因此失效；问题主要在于：

- 文档把实际完成度描述得过于绝对。
- 多按钮容器仍有一个遗留专用类 `.tds-device-actions`。
- 单按钮、文字按钮和非交互说明文字没有形成书面规则。
- 静态测试提示语写着“use `<TableActions>`”，实际断言却只禁止 `<Space>` 并要求列宽。

这会让后续开发者无法判断哪些情况必须包裹 `TableActions`，也可能继续复制专用容器。

## 3. 代码排查结果

### 3.1 公共组件的真实能力

| 文件与位置 | 当前能力 |
| --- | --- |
| `frontend/src/components/TableActions.tsx:3-23` | `div[role=group]`，可传无障碍名称；用于多操作居中、不换行 |
| `frontend/src/components/TableActionButton.tsx:5-32` | 40px 图标操作按钮；提供 `aria-label` 与 `title` |
| `frontend/src/index.css:1180-1190` | `.tds-table-actions`：`inline-flex`、4px 间距、居中、禁止换行 |
| `frontend/src/index.css:1825-1831` | `.tds-device-actions`：另一套相似的多按钮 Flex 容器，但不是公共组件，也没有显式 `flex-wrap: nowrap`/`white-space: nowrap` |

### 3.2 未统一经过 `TableActions` 的位置

| 文件与位置 | 当前形式 | 性质 |
| --- | --- | --- |
| `frontend/src/pages/AlertCenter/index.tsx:643-655` | 单个 `TableActionButton` 直接渲染 | 单操作；当前视觉和可访问名称正常 |
| `frontend/src/pages/Configuration/ConfigCascading.tsx:492-500` | 单个带文字 `Button` | 单操作；列宽偏大，已纳入 `INTERACTION-002` |
| `frontend/src/pages/CustomersAndDevices/index.tsx:770-810` | 三个 `TableActionButton` 包在 `.tds-device-actions` | 多操作；属于应迁移的重复容器 |
| `frontend/src/pages/ThreatIntel/index.tsx:455-506` | 条件渲染说明文字或单个 `TableActionButton` | 同一列既可能是非交互说明，也可能是单操作 |
| `frontend/src/pages/ThreatList/index.tsx:639-662` | 单个带文字的危险 `Button` | 单操作；有 `aria-label`，未使用公共图标按钮 |

这些位置说明“所有操作列都使用 `TableActions`”与代码事实不符，但也说明强制给每个单按钮增加 `role=group` 未必有实际价值。

### 3.3 文档与静态契约不一致

- `AI_PROJECT/Interaction/001_全局表格对齐与单行显示规范/02_修复结果.md:28` 写明所有操作列改用 `TableActions`。
- 同文档维护规则写明新增表格操作列使用 `TableActions`。
- `tests/test_table_layout_contract.py:196-206` 的实际断言只有：
  - 操作列片段中不得包含 `<Space`；
  - 操作列必须声明 `width`。
- 测试失败消息写着“use `<TableActions>`”，但测试并没有检查 `TableActions` 是否存在。

因此文档、测试提示语和实际约束表达了三种不同规则。

## 4. 根本原因

### 4.1 修复报告把“主要迁移”概括成“全部迁移”

第二阶段重点处理会换行的多按钮列，技术方向正确，但结果文档没有保留单按钮与专用容器的例外说明。

### 4.2 没有定义“操作列”内部内容的分类

操作列可能包含：

- 多个交互按钮；
- 单个交互按钮；
- 带文字的破坏性操作；
- 条件性的非交互说明文本。

这些内容不应机械地套用完全相同的语义容器，但当前规范没有区分。

### 4.3 历史专用样式没有在公共组件建立后清理

`.tds-device-actions` 与 `.tds-table-actions` 的职责高度重复，设备抽屉仍使用旧容器，形成两套实现。

### 4.4 静态测试采用宽松正则，无法验证 JSX 语义结构

当前契约适合检查列宽和禁止 `Space wrap`，不适合可靠判断一个 render 中有几个交互控件，也没有明确的例外清单。

## 5. 建议修复方案

### 5.1 先确立统一规则

建议采用以下规则，而不是强制所有单按钮都增加分组容器：

1. **两个及以上交互操作**：必须使用 `TableActions`，并传入可读的 `label`。
2. **单个图标操作**：允许直接使用 `TableActionButton`；必须有准确 `label`，列本身必须居中、定宽、单行。
3. **单个文字操作**：允许直接使用 Ant `Button`，但必须说明为何文字比图标更清晰，并具备可访问名称、焦点态和合理列宽。
4. **非交互说明文字**：使用 `TableCellText` 或状态组件，不应为了形式统一包进 `role=group`。
5. **专用多操作容器**：除非有公共组件无法表达的业务语义，否则不得新增；现有 `.tds-device-actions` 应迁移。
6. **破坏性操作**：无论采用何种容器，都必须保留确认或可撤销机制。

这套规则符合当前组件职责，也避免无意义的 ARIA 分组。

### 5.2 代码整改步骤

1. 将 `CustomersAndDevices/index.tsx:777-809` 的 `<div className="tds-device-actions">` 替换为 `<TableActions label={t('common.actions')}>`。
2. 回归通过后删除 `.tds-device-actions`；如仍有外部依赖，先将其作为 `.tds-table-actions` 的临时别名并登记移除期限。
3. `ConfigCascading` 成员单操作与列宽在 `INTERACTION-002` 中一起处理，优先改为 `TableActionButton`。
4. AlertCenter 的单个详情按钮可按新规则保持直接渲染，不需要为了“形式一致”增加无意义分组。
5. ThreatIntel 的非交互说明继续使用 `TableCellText`；可拉取时的单按钮保持准确标签和 Tooltip。
6. ThreatList 的文字删除按钮可以保留，但应在规范中登记为“单个文字破坏性操作”；若改为图标按钮，必须保留确认/事件冒泡控制和可访问名称。

### 5.3 文档整改步骤

修改 `001_全局表格对齐与单行显示规范/02_修复结果.md`：

1. 把“所有操作列改用 `TableActions`”修正为“所有多按钮操作列统一使用 `TableActions`；单按钮和非交互说明按公共单元格规则居中”。
2. 在页面清单中明确设备抽屉历史使用 `.tds-device-actions` 的情况；完成迁移后再更新为公共组件。
3. 维护规则改为上述分类规则，并补充 `TableActionButton`、`TableCellText` 的适用边界。
4. 不能把“源码已修改”“自测完成”“独立验收通过”混写；文档应记录实际完成状态。

### 5.4 契约测试整改步骤

1. 保留“操作列禁止 `Space`/`Space wrap`”和“必须有固定宽度”的现有断言。
2. 把误导性的失败消息改为真实要求，不要在未检查时声称必须使用 `TableActions`。
3. 增加“不得再出现 `.tds-device-actions`”的明确契约。
4. 对已知多按钮列维护一个小型展示面/组件清单，检查其使用 `TableActions`；不要用容易误判嵌套 JSX 的大范围正则统计按钮数量。
5. 为 `TableActions` 单元测试补充：`role=group`、可访问名称、追加 className、多个按钮保持子元素顺序。
6. 在 E2E 中检查多按钮组的几何居中、单行、键盘焦点和操作可点击；单按钮不应因为没有 `role=group` 被误报。

## 6. 潜在影响

- 将设备专用容器迁移到 `TableActions` 不应改变按钮行为，但要验证权限隐藏后 1/2/3 个按钮都能居中。
- 删除 `.tds-device-actions` 前必须全局搜索，防止遗漏隐藏引用。
- 强制所有单按钮使用 `TableActions` 会增加无意义 DOM/ARIA，因此不建议作为默认方案。
- 把文字按钮改为图标按钮会改变可发现性，必须保留提示和可访问名称；是否转换应按具体页面决定。
- 文档修正可能使“第二阶段已全部完成”的旧结论变得更保守，但这是恢复记录真实性，不是功能回退。

## 7. 验证方法与验收标准

### 7.1 静态检查

- `rg -n "tds-device-actions" frontend/src` 在迁移后无业务代码命中。
- 所有多按钮操作区都使用 `TableActions` 或有明确、经过评审的例外。
- 单按钮位置满足列宽、居中、单行和可访问名称要求。
- `02_修复结果.md` 的描述与源码、测试断言一致。

### 7.2 自动化验证

1. `python -m unittest tests.test_table_layout_contract -v`
2. `npm.cmd run lint`
3. `npx.cmd tsc --noEmit`
4. 运行 `TableActions`/`TableActionButton` 组件测试。
5. E2E 验证设备操作区在不同权限下显示 1/2/3 个按钮时均居中、不换行。

### 7.3 功能验证

- 查看数据流、编辑、解绑、查看详情、拉取、删除等操作仍触发原有处理逻辑。
- 权限门控、禁用、加载、Popconfirm、Tooltip、事件冒泡控制不发生变化。
- 键盘 Tab 可到达操作按钮，焦点可见，图标按钮名称可被辅助技术读取。

### 7.4 通过标准

- 公共规范、源码实现、静态契约和修复结果文档表达同一套规则。
- 不再存在未登记的多按钮专用容器。
- 不通过增加无意义包装来追求表面统一，不改变业务功能。

## 8. 本阶段结论

该遗留问题的核心不是当前页面严重错位，而是“文档声称全部统一，代码和测试实际采用分类处理”。建议正式确立多按钮必须 `TableActions`、单按钮可直接渲染、非交互文本使用 `TableCellText` 的规则，并迁移唯一的 `.tds-device-actions` 重复容器。本阶段未修改代码或既有修复文档。
