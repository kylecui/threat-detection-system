## 2. 修复结果总结

按方案 6.1 推荐方案，把 Harness 拆成“组件模块 + 启动入口”两个文件：

1. **新增组件模块 `ConfigCascadingHarness.tsx`**：
   - 从原入口原样移入：`ConfigProvider`、中英文 antd locale、`useTranslation`、`@/i18n`、全局与配置页 CSS、`useTheme`、`createAppTheme`、`ConfigCascading`、`CONFIGURATION_ACCENT`，以及 `HarnessShell` 的 JSX；
   - 唯一导出为 `export function HarnessShell()`；`CONFIGURATION_ACCENT` 不导出，避免触发同一规则的 `namedExport` 分支；
   - 不含 `createRoot`，也不引用 `react-dom`。
2. **原入口 `config-cascading.tsx` 收敛为纯启动文件**：只保留 React/ReactDOM、`ThemeProvider`、`AuthProvider`、导入的 `HarnessShell` 和 `createRoot(...).render(...)`。不再定义任何 React 组件。
3. **保持既有 Harness 契约（方案 6.2）**：
   - HTML 仍加载 `./config-cascading.tsx`，URL 仍为 `/e2e/harness/config-cascading.html`；
   - Provider 嵌套仍为 `ThemeProvider → AuthProvider → HarnessShell`（外层仍有 `React.StrictMode`）；
   - DOM 层级 `.tds-shell > .tds-content > .tds-content__inner > .tds-route-stage`、`data-testid="config-cascading-harness"`、强调色 `#9d7aea` 都不变。
4. **模块加载顺序**：入口先导入 `HarnessShell`，再导入两个 Provider。这样 i18n 与全局/配置页 CSS 仍在 Provider 模块之前加载，与拆分前一致（拆分前它们在原文件中位于 Provider 导入之前）。
5. **没有使用方案 6.3 中禁止的方式**：没有关闭规则、没有删除 `--max-warnings 0`、没有新增 ignore、没有行内 `eslint-disable`、没有修改 `node_modules`。

## 4. 测试结果

### 4.1 ESLint 规则复现与验证

本工作区无法访问 npm 仓库，无法安装项目的 ESLint 8.57.1 + `@typescript-eslint` 全套依赖。因此采用以下方式**单独验证导致门禁失败的那条规则**：

- 规则实现：直接使用你本机安装的 `eslint-plugin-react-refresh` **0.4.24**（`frontend/node_modules/eslint-plugin-react-refresh/index.js`，只读取，未修改）；
- 规则配置：与 `.eslintrc.cjs` 相同，`['warn', { allowConstantExport: true }]`，并开启未使用禁用注释报告；
- 解析：先用 TypeScript 自带的 `transpileModule` 去掉类型注解（保留 JSX、import/export、函数与变量声明），再交给工作区的 ESLint 10 运行该规则。

| # | 验证 | 结果 |
| --- | --- | --- |
| 1 | 修复前，`src` 和 `e2e` 下全部 46 个 `.tsx` | **1 个 warning**：`e2e/harness/config-cascading.tsx`，`HarnessShell`，“Fast refresh only works when a file has exports”（即复查报告中第 27 行的问题；行号因去掉类型和空行后有偏移）。与 Windows/Ubuntu 复查结果完全一致 |
| 2 | 修复后，全部 47 个 `.tsx`（含新增组件文件） | **0 个 warning、0 个 error** |
| 3 | 方法自检 | 起初用 esbuild 去类型时，`export default X` 被改写成 `export { X as default }`，规则因此误报了 31 条。改用 TypeScript 的 `transpileModule` 后，修复前结果恰好只有项目实际报告的那 1 条，说明当前方法与真实结果一致 |
| 4 | `src` 中已有的 5 处 `eslint-disable-next-line react-refresh/...` | 仍然有效，未报“未使用的禁用注释”。本轮没有新增任何禁用注释 |
