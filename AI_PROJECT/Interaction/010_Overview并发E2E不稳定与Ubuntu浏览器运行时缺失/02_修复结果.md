## 2. 修复结果总结

### 2.1 工作线 A：Overview 用例按快照响应同步

`frontend/e2e/overview-trend.spec.ts` 按方案 6.1 重写：

1. 新增 `waitForSnapshot(page, hours)`，同时匹配 3 个条件：路径以 `/api/v1/assessment/overview-snapshot` 结尾、`hours` 参数相等、`response.ok()`。超时 15 秒（局部）。
2. 新增 `openOverview(page)`：**先**创建 `waitForSnapshot(page, "24")`，再 `page.goto("/overview")`，最后等待响应完成。3 条用例都通过它进入页面。
3. 7 天、30 天切换使用 `Promise.all([waitForSnapshot(page, hours), item.click()])`，监听先于点击建立，不会漏掉快速返回的 Mock 响应。
4. 删除了只记录请求的 `hours` 数组和 `expect.poll(() => hours.includes(...))`。
5. 响应完成后，在趋势面板范围内等待图表或空状态，渲染等待使用局部 15 秒超时。全局 `expect.timeout`、workers、retries 均未修改。
6. 范围切换后同时断言 3 点：
   - 对应 Segmented 项已选中；
   - 对应快照响应已成功；
   - 刷新按钮的 loading 状态已结束，图表和 Canvas 仍然存在。

   其中“loading 已结束”是方案之外的补充：页面在设置趋势数据之后才会在 `finally` 中清除 loading。只断言“图表可见”时，旧范围的图表还在页面上，测试可能提前通过；加上这一条就能证明新范围的状态已经写入。
7. 保留了 `pageerror` 断言和“无未登记请求”断言。普通数据与全 0 数据都断言恰好 1 个 Canvas 且没有空状态；空数组断言只有空状态、没有图表。

### 2.2 工作线 B：版本锁定的离线 Playwright 运行环境

新增两个测试专用脚本，都放在 `scripts/testing/`，不会进入生产包：

**`prepare_playwright_image.sh`**
- `save [目录]`：在可联网的 x86_64 Linux 机器上，从 `package-lock.json` 读取 Playwright 版本（同时校验 `@playwright/test` 与 `playwright-core` 一致，当前为 1.59.1），然后：
  - 拉取 `mcr.microsoft.com/playwright:v1.59.1-noble`；
  - 生成 `playwright-v1.59.1-noble.tar.gz`、`.sha256`；
  - 生成 `.meta`，记录镜像 ID、RepoDigest、版本和时间。
  - 拒绝写入 `outputs/v<version>/`。
- `load [目录]`（默认 `/home/jzzn/e2e-images`）：在构建机上依次执行：
  - 检查归档目录和 Docker 根目录的剩余空间，默认至少 4 GiB；
  - `sha256sum -c` 校验；
  - `docker load`，并核对载入后的镜像 ID 与 `.meta` 一致。
  - 脚本不执行任何 prune 或删除操作。

**`run_frontend_e2e_ubuntu.sh [Playwright 参数]`**
- 运行前预检：
  - 主机为 Linux x86_64，Docker 可用；
  - 锁文件版本与镜像标签一致；
  - 镜像已离线载入（不会在线下载）；
  - 报告目录与 Docker 根目录剩余空间（默认 ≥ 4 GiB）；
  - 可用内存（默认 ≥ 3 GiB，其中 1 GiB 用于容器共享内存）。
- 容器启动方式：`--shm-size=1g`、`--init`；以当前用户的 UID/GID 运行，不会在宿主机留下 root 文件；源码以只读方式挂载。
- 容器内依次执行：
  1. 复制源码，排除宿主机的 `node_modules`、`dist` 和既有报告；
  2. 按锁文件执行 `npm ci`，可用 `TDS_E2E_NPM_REGISTRY` 指定可达的源；
  3. 核对安装的 `@playwright/test` 等于锁定版本，并核对镜像中确实有对应的 `chromium-<revision>` 和 `chromium_headless_shell-<revision>` 目录，不一致时在运行任何测试前失败；
  4. 运行测试，附加参数 `--forbid-only --reporter=list,html,json`。
- 不指定 `--workers` 时自动使用 `--workers=4`。容器内把 `CI` 设为空，所以配置文件中的“CI 单 worker、2 次重试”不会生效，不会用单 worker 结果替代完整回归。
- 报告写入 `outputs/e2e-reports/<UTC 时间>/`（该目录已在 `.gitignore`、`.dockerignore` 中，也不会被打包），包含：
  - `html/`、`results.json`、`test-results/`、`console.log`；
  - `run-info.txt`：镜像、镜像 ID、锁定版本、参数、起止时间、退出码；
  - `container-script.sh`：容器内实际执行的脚本。
- 脚本退出码等于 Playwright 的退出码，测试失败时不会返回 0。

`AI_PROJECT/RELEASE_PROCESS.md` 新增“前端质量门禁（打包前必须通过）”一节，写明 lint/类型/单测/构建/Ubuntu E2E 的执行顺序和镜像准备步骤。构建命令中写死的 `3.1.37` 改为读取 `VERSION`，并明确“发布前先升版本、不得覆盖已有归档”。
