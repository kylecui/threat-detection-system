## 2. 最终结论摘要

核心表格契约已经正确落地，以下关键问题已得到实质解决：

- 全部业务表格的表头和普通数据单元格具有全局水平居中、垂直居中和单行显示规则。
- 源码中已无表格列 `align: left/right`，24 个表格均有数值型 `scroll.x`，已无 `max-content`。
- 默认、middle、small 三种 Table Token 密度已经统一。
- 排序、筛选、选择、展开、状态标签和操作按钮组具备统一居中基础。
- 长文本、状态标签和操作按钮已有公共组件或稳定的 Ant Design 省略方案。
- Lint、完整 TypeScript 检查、50 项前端单元测试、生产构建、12 项表格静态契约和 24 项发布契约均通过。
- 在真实 Chrome 中，已验证的表格没有发现居中、nowrap、垂直对齐和页面根节点横向溢出问题。

但当前仍不能判定“彻底解决”，原因有二：

1. `ConfigCascading` 的操作列仍明显过宽，违反原需求“紧凑适度、避免列间距过大和内容松散”。这是实际实现遗留，不只是测试问题。
2. 第二阶段新增的 E2E 存在错误 Mock 和静默跳过机制，且未覆盖配置级联、弹窗/抽屉、缩放、语言和主题矩阵。第二阶段文档所称“全路由表格巡检”并不完整。

因此按照原始要求的严格验收口径，本次结论为 **不通过**；核心修复可保留，只需针对第 6 节问题整改后复验，无需推翻现有全局方案。

## 6. 遗留问题与整改建议

### [P2] 配置级联操作列明显过宽

- 位置：
  - `frontend/src/pages/Configuration/ConfigCascading.tsx:387`，两个文字按钮操作列宽度 220px。
  - `frontend/src/pages/Configuration/ConfigCascading.tsx:451`，四个文字按钮操作列宽度 560px。
- 类别：视觉一致性 / 信息密度 / 响应式。
- 影响：操作列占用过多横向空间，迫使业务字段更早进入横向滚动；与其他页面 108/152/200px 的操作列体系差距明显，违背“紧凑适度、避免内容松散”。
- 实测：系统 Chrome 中英文四按钮组自身约 353px，加单元格左右内边距后约 377px；560px 比完整显示所需宽度多约 183px。
- 整改建议：
  1. 优先改为与全站一致的 `TableActionButton` 图标操作，两个操作使用约 108px，四个操作使用约 200px。
  2. 若必须保留文字按钮，两个按钮列建议重新实测至约 152px，四按钮英文列约 400px，并同时验证中文/英文。
  3. 相应下调分组表 `scroll.x`，使其重新等于列宽总和。

### [P2] E2E Mock 错误导致有效桌面表格被静默跳过

- 位置：
  - `frontend/e2e/helpers/auth.ts:107-126`
  - `frontend/e2e/table-layout.spec.ts:41-44`
- 类别：测试完整性 / 回归风险。
- 影响：Pipeline、ML 的桌面和 Tablet 表格在 CI 中没有真正执行断言；未来这些页面回归时测试仍可能显示“总体通过”。
- 整改建议：
  1. 为 `/api/v1/system/health` 和全部 ML GET 接口提供符合 TypeScript 类型的 Mock。
  2. 只允许明确登记的移动端卡片路由跳过表格检查。
  3. 桌面/Tablet 路由未出现预期表格时直接失败，不得调用通用 `test.skip`。

### [P2] E2E 未覆盖全部 24 张表及原定验证矩阵

- 位置：`frontend/e2e/table-layout.spec.ts:11-29,41-72`
- 类别：响应式 / 测试完整性 / 可访问性。
- 影响：
  - 路由数组不包含 `ConfigCascading` 对应的 3 张表。
  - 选择器只检查 `.tds-content`，没有打开和检查 `.ant-modal` / `.ant-drawer` 中的表格。
  - 只覆盖 1440、1024、390 三档视口；没有把第一阶段约定的 1920/1280/768、80%-200% 缩放、中文/英文、浅色/深色纳入可重复测试。
  - 操作按钮只检查是否同一行，没有检查按钮组中心与单元格中心的几何偏差。
- 整改建议：
  1. 增加配置级联组件级或可访问路由测试，打开成员弹窗。
  2. 在客户管理用例中真实打开设备抽屉，并把本次手工补测固化到 E2E。
  3. 增加至少 1920、1280、768 三档和中英文主题矩阵；缩放可作为独立 Chromium CDP/浏览器验收任务。
  4. 校验表格内部 `scrollWidth > clientWidth` 时可滚动，同时保证页面根节点不横向溢出。

### [P3] 第二阶段文档对操作容器统一程度描述不准确

- 位置：`02_修复结果.md` 第 2.6 节及第 3.3 节相关描述。
- 影响：后续维护者可能误以为所有操作列都强制经过 `TableActions`，而静态契约实际只禁止 `Space` 并要求列宽。
- 整改建议：修正为“多按钮列统一使用 `TableActions`；单按钮和已登记专用容器由全局单元格规则居中”，或将剩余位置全部迁移后保留原表述。
