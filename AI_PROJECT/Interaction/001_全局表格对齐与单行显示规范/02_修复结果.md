## 2. 修复结果总结

1. **建立唯一的全局表格契约**：在 `index.css` 中用一组作用域为 `:is(.tds-content, .ant-modal, .ant-drawer)` 的规则统一所有业务表格。表头、正文、选择列、展开列都水平居中、垂直居中、单行显示（`white-space: nowrap`）。作用域包含 `.ant-modal` / `.ant-drawer`，因为弹窗和抽屉内的表格通过 Portal 渲染在 `.tds-content` 之外，原方案的示例选择器覆盖不到它们，例如配置级联的“成员”弹窗和客户设备抽屉。
2. **统一密度**：三种尺寸（默认 / `middle` / `small`）的 Token 统一为 `cellPaddingBlock 3px`、`cellPaddingInline 12px`、正文 14px。表头 40px、数据行 48px、嵌套表最低 44px 由 CSS 统一控制；5 个页面级 CSS 中重复或冲突的表头高度、行高、内边距、字号、字重覆盖已删除。
3. **排序 / 筛选 / 选择 / 展开**：排序图标、筛选图标与标题作为一个整体居中。选择列固定 8px 内边距，保证 16px 复选框位于 32px 列的正中。
4. **溢出策略**：固定布局表格中，超长单行内容在本单元格内裁切并显示省略号，不再覆盖相邻列。固定列（`fixed`）不裁切，以保留阴影。横向溢出只在表格内部滚动，并设置 `overscroll-behavior-inline: contain`。
5. **公共组件**：
   - 新增 `TableCellText`：单行省略，只有内容真实溢出时才显示完整值 Tooltip。
   - 新增 `TableActions`：操作按钮组 `inline-flex`、居中、禁止换行，带 `role="group"` 和可读名称。
   - `.tds-status-tag` 改为 `inline-flex` 居中。表格内 `Tag` 右外边距归零。
6. **逐页清理**：全部 24 个表格实例都已完成。
   - 移除全部 18 处 `align: right`，改为 `center`。
   - 为所有列补齐稳定宽度；每张表的 `scroll.x` 都不小于列宽总和，`max-content` 已全部移除。
   - 多按钮操作列统一使用 `TableActions`，原 `Space` / `Space wrap` 已移除；单按钮操作列（告警子表“查看”、设备列表“解绑”、威胁列表文字“删除”、情报订阅源“拉取”）和非交互说明（情报订阅源“无需拉取/不支持拉取”）按公共单元格规则居中，未包 `TableActions`；设备抽屉当时仍使用历史容器 `.tds-device-actions`。
     > 【INTERACTION-005 勘误，2026-10-27】原文“所有操作列改用 `TableActions`”表述过度，已按代码事实修正；`.tds-device-actions` 已在 INTERACTION-005 中迁移为 `TableActions` 并删除，单按钮规则见第 7 节。
   - 长文本（标题、名称、邮箱、URL、模型路径、描述等）改用 `TableCellText`。
   - 用户角色改为“首个角色 + `+N`”单行显示，Tooltip 中列出全部角色。
7. **回收威胁列表专属样式**：`.tds-threat-list-table` 中的居中、排序、选择列规则已并入全局规则后删除，只保留嵌套表圆角样式。
8. **自动化回归**：新增静态契约测试（12 项）、组件单元测试，以及 Playwright 全路由表格巡检用例。

## 5. 与第一阶段方案的差异说明

| 方案原文 | 实际实施 | 原因 |
| --- | --- | --- |

| 数据行 48px，同时保留 40px 图标按钮 | 单元格上下内边距取 3px，由 CSS `height` 保证 48px | 4px 时按钮行为 49px（40+8+1px 分隔线），3px 才能让所有行都是 48px |
| 列宽字典：两个图标 104px、三个图标 144px、MAC 168-184px | 两个图标 108px、三个图标 152px、四个图标 200px；MAC 统一 192px | 12px 左右内边距下按钮组实际需要 40n+4(n-1)+24 px；MAC 标识符（带内边距和边框的等宽字体徽标）在 SF Mono / Liberation Mono 下需约 189px，184px 会被截掉约 5px |

## 6. 未解决问题与需在本机补跑的验证

1. **必须在本机执行（本环境无法安装依赖）**：

   ```powershell
   cd F:\codex\threat-detection-system\frontend
   npm run lint
   npm run build          # 含 tsc 完整类型检查
   npm test               # vitest，含新增 TableCellText.test.tsx
   npx playwright test    # 含新增 e2e/table-layout.spec.ts
   cd F:\codex\threat-detection-system
   python -m unittest tests.test_table_layout_contract
   python -m unittest tests.test_release_contract
   ```

2. **`e2e/table-layout.spec.ts` 未在真实应用上运行过**。它依赖 `e2e/helpers/auth.ts` 的接口模拟；如果某路由的接口没有被模拟，表格可能只有表头（仍可校验）。若 390px 视口下某页面因非表格元素（筛选栏、工具栏）原本就有页面横向溢出，该断言会失败。这属于本问题范围外的既有问题，需要在复查时区分。
3. **深色主题、真实字体（Aptos / 微软雅黑 / Consolas）未做截图验证**。本次没有改动任何颜色，深色主题风险低；测试页使用容器内的替代字体，比 Windows 字体略宽，所以列宽结论在 Windows 上偏保守。
