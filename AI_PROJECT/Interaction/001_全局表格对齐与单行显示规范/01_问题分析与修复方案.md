## 2. 问题总结

前端当前共有 **12 个页面文件、24 个 `Table/ProTable` 实例**。表格均由 Ant Design / Ant Design Pro 提供，但项目只统一了颜色、边框和部分字体，没有建立“所有表头、数据、操作、状态均居中，默认不换行，空间不足时由表格区域横向滚动”的全局表格契约。

当前表现不是单个页面的偶发问题，而是以下问题叠加形成的系统性不一致：

1. 全局样式仅设置正文单元格垂直居中，没有设置水平居中和默认单行显示。
2. 只有威胁列表使用专属 CSS 强制居中，其余页面依赖 Ant Design 默认左对齐或页面各自配置。
3. 多个数字列显式配置为右对齐，与本次全局居中要求直接冲突。
4. 页面级 CSS 分别控制表头和行高，公共 Token 又只配置默认尺寸，导致 `small`、`middle`、默认尺寸之间密度不一致。
5. 部分表格缺少完整列宽和 `scroll.x`，空间不足时只能压缩、换行或挤压操作按钮。
6. 部分长文本仅设置 `ellipsis`，但没有列宽；部分自定义渲染没有统一的省略号与完整内容提示。
7. 排序标题、选择框、展开按钮、操作按钮组和状态标签没有统一的居中容器。
8. 现有自动化测试只检查一处设备管理表头不换行，未覆盖全局表格规范。

结论：应采用“**全局 Token + 全局表格基础样式 + 公共长文本/操作单元格组件 + 逐页列宽与滚动配置清理 + 自动化回归**”的方案。仅在每个页面零散增加 `align: "center"` 会继续产生遗漏和维护分叉。

## 4. 根本原因

### 4.1 缺少全局表格对齐与单行契约

`frontend/src/index.css:1035-1046` 只定义了表头字体、颜色和正文单元格 `vertical-align: middle`，没有定义：

- `text-align: center`
- 表头/正文统一 `white-space: nowrap`
- 排序标题容器的居中方式
- 选择列和展开列的居中方式
- 操作按钮组、状态标签的统一布局方式

Ant Design 默认将普通列左对齐，因此没有显式配置的列自然保持左对齐。

### 4.2 居中规则只在威胁列表局部存在

`frontend/src/index.css:1052-1068` 仅对 `.tds-threat-list-table` 强制表头、正文、选择列、展开列和排序器居中。`frontend/src/pages/ThreatList/index.tsx:533-725` 的列定义也逐列配置了 `align: "center"`。

这说明项目已有正确方向，但实现被限定在单个页面，其他 21 个表格实例不会继承该规则。继续复制这一段 CSS 会扩大重复，应将其提升为 `.tds-content` 内全部业务表格的基础规则，再保留少量确有业务必要的局部覆盖。

### 4.3 多个列定义显式右对齐

以下位置使用了 `align: "right"` 或 `align: 'right'`，会覆盖 Ant Design 默认值，并与本次“所有数据统一居中”要求冲突：

- `frontend/src/pages/AlertCenter/index.tsx:433,565,572,632`
- `frontend/src/pages/CustomersAndDevices/index.tsx:1382`
- `frontend/src/pages/MlDetection/index.tsx:268,278`
- `frontend/src/pages/Overview/index.tsx:318,325,332,339,370,378`
- `frontend/src/pages/PipelineHealth/index.tsx:221`
- `frontend/src/pages/ThreatIntel/index.tsx:218,260,274,392`

仅增加普通优先级的全局 CSS 无法可靠覆盖组件生成的对齐样式。实施时既要将这些列配置改为居中，也要提供全局兜底，避免以后新增列再次退回左/右对齐。

### 4.4 密度由 Token 与页面 CSS 分散控制

`frontend/src/App.tsx:960-966` 的 Table Token 只设置：

- `cellPaddingBlock: 13`
- `cellPaddingInline: 14`

但 Ant Design 同时支持 `cellPaddingBlockMD/SM`、`cellPaddingInlineMD/SM`。项目内既有 `small` 也有 `middle` 和默认尺寸，因此未设置的尺寸继续使用组件默认值。

与此同时：

- `frontend/src/pages/Overview/overview.css:352-364` 使用表头 38px、数据行 48px。
- `frontend/src/pages/operations.css:195-205` 使用另一套页面级表格高度。
- `frontend/src/pages/Configuration/configuration.css:269-276` 仅指定正文行 48px。
- `frontend/src/pages/investigate.css:130-138` 只指定字体和正文最小高度。

结果是视觉上相似的表格由不同层级控制，修改其中一处无法保证全局一致。

### 4.5 列宽与横向滚动配置不完整

高风险位置包括：

- `frontend/src/pages/Configuration/ConfigCascading.tsx:353-481`：三组列定义大量缺少 `width`；`527-549` 和 `646-653` 的三个表格没有 `scroll.x`。
- `frontend/src/pages/Configuration/ConfigCascading.tsx:437`：操作区使用 `<Space wrap>`，空间不足会把按钮换成多行。
- `frontend/src/pages/PipelineHealth/index.tsx:464-471`：无 `scroll.x`。
- `frontend/src/pages/MlDetection/index.tsx:649-656`：无 `scroll.x`，模型路径为长字段。
- `frontend/src/pages/Configuration/AIConfig.tsx:478-625`：Base URL 等长字段缺少稳定宽度，表格使用 `scroll.x: 'max-content'`，不同数据会导致列宽波动。
- `frontend/src/pages/Configuration/PluginConfig.tsx:256-325`：插件 URL 省略但没有稳定列宽，同样依赖 `max-content`。

在没有列宽总和和横向滚动的情况下，浏览器会压缩单元格，直接诱发标题换行、状态标签挤压、按钮重叠或表头与内容视觉错位。

### 4.6 长文本处理没有统一策略

现有实现同时存在以下三种状态：

1. `NetworkIdentifier` 已具备单行、省略和完整值提示，是正确基础。
2. Base URL、插件 URL、模型路径使用 `ellipsis`，但列宽和 Tooltip 实现不一致。
3. 告警标题、描述、用户角色、客户/租户名称、分组名称等长内容缺少统一处理。

直接对所有 `td` 使用 `text-overflow: ellipsis` 会误裁切状态、按钮和复合内容。应通过公共长文本单元格包装器控制省略，并明确哪些字段必须完整显示。

### 4.7 复合单元格没有统一居中容器

- `.tds-device-actions` 已在 `frontend/src/index.css:1684-1690` 使用 flex 居中，但该模式未覆盖其他操作列。
- `.tds-status-tag` 在 `frontend/src/index.css:1226-1235` 已固定高度和禁止换行，但没有使用 `inline-flex + align-items + justify-content`，垂直/光学居中仍依赖行高。
- 普通 `Tag` 仍可能保留默认右边距；用户角色多标签在窄列内可能换行。
- 排序列、选择列、展开列的居中只在威胁列表专属样式中存在。

### 4.8 自动化测试无法阻止回归

现有测试证据：

- `tests/test_release_contract.py:283-304` 只检查设备管理抽屉表头存在 `white-space: nowrap`，没有遍历其他表格。
- `frontend/e2e/audit-regression.spec.ts:228-229` 验证威胁列表排序结果，但不检查对齐、换行、列宽和滚动。
- `frontend/e2e/threat-list.spec.ts:14` 仅验证表格可见。

因此，即使某次人工修复了页面，后续新增列或调整 CSS 仍可能无提示地破坏全局规范。

## 5. 建议修复方案

### 5.1 第一阶段：建立唯一的全局表格规范

修改 `frontend/src/App.tsx` 的 Table Token，统一默认、`middle`、`small` 三种尺寸的单元格内边距。建议基线：

- 表头高度：40px。
- 数据行高度：48px；嵌套紧凑表格最低 44px，但视觉基线、字体和对齐保持一致。
- 表头字体：12px / 600。
- 数据字体：14px。
- 水平内边距：12px。
- 状态标签高度：24px。
- 图标操作按钮：40×40px，保持现有可点击面积。

在 `frontend/src/index.css` 的 `.tds-content` 业务范围内建立全局规则，至少覆盖：

```css
.tds-content .ant-table-thead > tr > th,
.tds-content .ant-table-tbody > tr > td,
.tds-content .ant-table-selection-column,
.tds-content .ant-table-row-expand-icon-cell {
  text-align: center !important;
  vertical-align: middle !important;
  white-space: nowrap;
}

.tds-content .ant-table-column-sorters,
.tds-content .ant-table-selection-column .ant-checkbox-wrapper {
  justify-content: center;
}
```

实施时需确认排序、筛选图标仍与标题作为一个整体居中，不应只居中文字而把图标留在单元格右侧。现有 `.tds-threat-list-table` 专属居中规则在全局规则稳定后应删除或缩减，避免同一规范维护两份。

### 5.2 第二阶段：统一公共单元格组件

建议新增或扩展两类公共能力：

1. `TableCellText`（建议新文件 `frontend/src/components/TableCellText.tsx`）
   - 只用于标题、描述、名称、URL、模型路径、邮箱等可省略长字段。
   - 单行省略。
   - 仅在内容实际溢出时显示 Tooltip，Tooltip 展示完整值。
   - 容器设置 `min-width: 0`，防止 flex 子项撑破单元格。
2. `TableActions`（可新增组件或全局类）
   - `display: inline-flex`、水平/垂直居中、固定间距、禁止换行。
   - 继续复用 `TableActionButton`，保留 `aria-label`、`title`、键盘焦点和 40px 点击区域。

同时调整 `SemanticStatusTag` / `.tds-status-tag` 为 `inline-flex` 居中，并将普通表格标签的默认外边距归零。IP、MAC 继续复用 `NetworkIdentifier`；时间和数字使用 `font-variant-numeric: tabular-nums`，不省略关键值。

### 5.3 第三阶段：建立列宽字典与滚动规则

不要按单个截图临时拖宽列。建议使用以下字段宽度基线：

| 字段类型 | 建议宽度 |
| --- | ---: |
| 序号/ID | 72-96px |
| 短状态/等级 | 96-120px |
| IP 地址 | 136-152px |
| MAC 地址 | 168-184px |
| 日期时间 | 176-192px |
| 普通数字/次数/评分 | 96-120px |
| 用户、客户、租户、设备名称 | 160-220px |
| 标题、描述、URL、路径 | 220-320px，超出省略并提示 |
| 单个图标操作 | 64px |
| 两个图标操作 | 104px |
| 三个图标操作 | 144px |
| 多个文字按钮 | 按按钮实际总宽度设置，禁止换行 |

每张表都应：

1. 为所有关键列指定稳定 `width`。
2. 将 `scroll.x` 设置为列宽总和或经验证的固定最小宽度，不依赖数据内容随机变化。
3. 只有确实需要固定列时使用 `fixed`，并确认固定列宽已明确。
4. 横向滚动只发生在表格内容区域，不允许页面根节点出现水平滚动条。
5. 设置 `overscroll-behavior-inline: contain`，避免触控板横向滚动带动整个页面。
6. 保持设备管理抽屉现有“宽抽屉内优先完整适配”的契约；只有在更窄视口无法容纳时才启用表格内部滚动，不能缩小抽屉或压缩操作列。

### 5.4 第四阶段：逐页清理，按风险实施

#### A. 最高优先级：配置级联

文件：`frontend/src/pages/Configuration/ConfigCascading.tsx`

- 为继承、分组、成员三组 columns 补齐宽度和 `align: "center"`。
- 将 `:437` 的 `<Space wrap>` 改为禁止换行的公共操作容器。
- 三张表分别配置与列宽总和相匹配的 `scroll.x`。
- 弹窗内成员表保持弹窗尺寸不变，只让表格区域内部滚动。
- 长分组名、实体名、来源等使用 `TableCellText`。

#### B. 高优先级：告警、总览、情报、客户设备

- `AlertCenter/index.tsx:368-646`：移除评分/数量右对齐；补齐告警标题、责任人、MAC、时间和三级表格的居中；操作列按按钮数量重新核定宽度；分组展开表继承同一规范。
- `Overview/index.tsx:277-403`：MAC/IP/时间、评分、次数、IP 数、端口数全部居中；保留现有移动端替代卡片，不让桌面表格规则破坏移动端呈现。
- `ThreatIntel/index.tsx:213-458`：ID、置信度、目击次数、指标数量、状态、时间和操作统一居中；URL/来源使用稳定宽度与完整值提示。
- `CustomersAndDevices/index.tsx`：四张表统一列宽、状态、标识符和操作列；攻击事件的响应端口改为居中；保留现有抽屉 z-index、筛选、固定列及详情交互。

#### C. 高优先级：用户、AI、ML

- `UserMgmt/index.tsx:219-322`：角色标签改为单行容器；超出时显示“前 N 个 + 数量”或单行省略并 Tooltip，避免标签换行撑高行。
- `AIConfig.tsx:478-625`：为 Base URL、模型、供应商、所有者、状态、操作补齐宽度和居中；将 `max-content` 改为经列宽总和计算的稳定滚动宽度。
- `MlDetection/index.tsx:239-296`：阈值与 Alpha 改为居中；模型路径使用公共长文本单元格；添加横向滚动。

#### D. 中优先级：流水线、插件、租户

- `PipelineHealth/index.tsx:198-248`：延迟改为居中，服务标识符使用稳定宽度，补充 `scroll.x`。
- `PluginConfig.tsx:256-325`：插件 URL、请求方式、状态、操作统一宽度和居中，URL 使用完整值提示。
- `TenantMgmt/index.tsx`：在现有宽度基础上补齐全列居中、状态/操作容器与横向溢出验证。

#### E. 正向样例回收：威胁列表

`ThreatList/index.tsx:533-725` 已逐列居中，且三张表已有滚动配置。实施时应将其作为行为基线，验证全局规则与排序、展开、选择列兼容；确认无差异后移除重复的页面专属居中 CSS，只保留真正特有的嵌套表格样式。

### 5.5 第五阶段：清理页面级密度覆盖

完成全局 Token 后，逐一审查以下 CSS：

- `frontend/src/pages/Overview/overview.css:352-364`
- `frontend/src/pages/operations.css:195-205`
- `frontend/src/pages/Configuration/configuration.css:269-276`

## 6. 潜在影响与控制措施

| 潜在影响 | 原因 | 控制措施 |
| --- | --- | --- |
| 长文本列让表格整体变宽 | 全局禁止换行 | 使用字段宽度字典、局部省略和表格内部横向滚动 |
| `!important` 覆盖个别历史列配置 | 需要兜底覆盖组件生成的左右对齐 | 同时清理显式左右对齐；规则只作用于 `.tds-content` 业务表格 |
| 排序/筛选图标视觉偏移 | 标题内部为 flex 结构 | 单独验证 `.ant-table-column-sorters` 和筛选触发器的整体居中 |
| 固定列遮挡或阴影错位 | 列宽与 `scroll.x` 不匹配 | `scroll.x` 使用列宽总和；对首尾固定列执行浏览器截图和坐标验证 |
| 操作列变宽 | 40px 点击目标和禁换行需要空间 | 按按钮数量精确计算宽度，不使用过宽的统一操作列 |
| 多标签信息被省略 | 角色/状态复合内容可能很长 | Tooltip 展示完整列表，或显示“前 N 个 + 数量”，不丢失信息 |
| 移动端阅读成本增加 | 单行表格天然需要横向浏览 | 保留现有移动端卡片替代；其他页面使用表格内部横向滚动 |
| 页面级 CSS 与新 Token 冲突 | 历史样式分散 | 建立样式优先级清单，逐个删除重复覆盖，并以计算样式测试兜底 |

本方案不修改数据结构、接口请求、排序逻辑、筛选参数、分页、权限、行选择、弹窗/抽屉尺寸或业务按钮行为。
