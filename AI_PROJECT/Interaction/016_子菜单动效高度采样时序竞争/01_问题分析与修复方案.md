## 2. 问题描述

`frontend/e2e/navigation.spec.ts` 的“submenu uses measured height and synchronized enter and leave motion”用例用于验证二级菜单收起/展开时具备动态高度、透明度和位移动画。

当前收起阶段先等待 class：

```ts
await expect(submenu).toHaveClass(/tds-submenu-motion-leave-active/);
```

随后另起一次浏览器执行读取样式：

```ts
const style = window.getComputedStyle(node);
height: Number.parseFloat(style.height)
```

Ubuntu 全量并发运行中，class 断言曾经观察到约 210ms 的 `leave-active` 窗口，但在下一次 `evaluate` 真正执行前动画已经结束并完成样式清理，`getComputedStyle(node).height` 返回 `auto`。`Number.parseFloat('auto')` 得到 `NaN`，最终在 `toBeGreaterThanOrEqual(0)` 失败。

运行特征：

- 全量 E2E 4 workers：该用例失败 1 次，收到 `NaN`；
- `navigation.spec.ts --workers=4 --repeat-each=3`：96/96 通过，该用例 3/3 通过；
- `INTERACTION-014` 新拆分的四个工作区用例在上述三轮中 12/12 通过。

因此原“四场景串行导致总超时”已经修复；当前是同文件另一个相关动效用例的低频采样竞争。

## 3. 根本原因

### 3.1 class 断言与样式读取不是同一个原子快照

`toHaveClass` 是 Playwright 自动重试断言。它在某一时刻看到 `leave-active` 后返回，但 `submenu.evaluate` 需要经过下一次驱动通信和页面任务调度。CSS 收起动画只有 210ms；4-worker 全量并发下，两步之间足以跨过动画结束边界。

这属于典型的 TOCTOU（检查时和使用时不一致）：测试证明“刚才出现过 active class”，却把“稍后读取到的样式”当作同一 active 帧。

### 3.2 对 CSS `height` 的解析缺少有限数校验

`frontend/e2e/navigation.spec.ts:481-490` 直接对 `getComputedStyle().height` 执行 `Number.parseFloat`，没有保留原始值，也没有 `Number.isFinite` 防护。`auto`、空字符串或节点状态变化都会转为 `NaN`，失败信息只显示 `NaN`，无法直接说明采样时 class、内联高度和实际矩形高度是什么。

### 3.3 测试重复实现了一个比生产代码更脆弱的高度读取方式

生产动画在 `frontend/src/App.tsx:277-287` 的 `readCurrentSubmenuStyle` 中使用 `node.getBoundingClientRect().height`，并对 opacity 做有限数保护；动态展开目标使用 `node.scrollHeight`。测试却使用 `parseFloat(computedStyle.height)`，与生产实现的测量来源不一致。

这说明当前失败不支持“产品动画高度为 NaN”的结论。相反，失败来自测试自己的采样和解析方式。

### 3.4 现有 MutationObserver 只保护四个工作区场景

`frontend/e2e/navigation.spec.ts:33-42` 的 `recordClassHistory` 会在点击前记录 class 变化，解决了 `INTERACTION-014` 中普通轮询错过短暂 leave class 的问题。但该 recorder 只被四个参数化工作区场景使用；第 462 行的 measured-height 用例仍采用“先等 class、再单次取样”的旧方式。

### 3.5 仅把读取方式改成矩形高度仍可能产生假通过

`getBoundingClientRect().height` 始终是有限数，但如果仍在动画结束后读取，隐藏菜单的高度会是 0，也满足当前 `0 <= height <= naturalHeight`。因此只替换 API、但不把“active class”和“高度样本”关联到同一帧，会把时序竞争从显式 `NaN` 变成潜在假通过。

## 5. 详细修复方案

### 5.1 在点击前安装动效帧 recorder

首选方案是把现有 `recordClassHistory` 扩展或新增为 `recordSubmenuMotionFrames`，并在触发收起/展开前安装。recorder 应同时使用：

- `MutationObserver` 观察 `class` 和 `style`；
- `requestAnimationFrame` 在 active 期间采集真实渲染帧；
- 节点自有的测试专用属性保存样本，沿用当前 `__tdsClassHistory` 的实现方式，不污染业务状态。

每个样本至少记录：

```ts
{
  time: performance.now(),
  className: node.className,
  inlineHeight: node.style.height,
  computedHeight: getComputedStyle(node).height,
  rectHeight: node.getBoundingClientRect().height,
  scrollHeight: node.scrollHeight,
  maxHeight: getComputedStyle(node).maxHeight,
  opacity: getComputedStyle(node).opacity,
  transform: getComputedStyle(node).transform,
  transitionDuration: getComputedStyle(node).transitionDuration,
}
```

recorder 必须提供显式清理：断开 observer、取消 rAF，并在测试结束后移除节点上的临时属性，避免同一页面后续用例积累观察器。

### 5.2 用同一帧同时证明“active”和“高度有效”

收起阶段不再使用“先 `toHaveClass`、再单次 `evaluate`”的两步方式。应从 recorder 历史中寻找同一个样本，且该样本同时满足：

- `className` 含 `tds-submenu-motion-leave-active`；
- `Number.isFinite(rectHeight)`；
- `0 <= rectHeight <= naturalHeight`；
- `transitionDuration` 包含 `0.21s`；
- `maxHeight === 'none'`；
- opacity 和 transform 可解析且符合收起方向。

展开阶段同样从 enter-active 样本中验证：

- active class 与样本属于同一帧；
- 目标内联高度是有限像素值且等于当时的 `scrollHeight`；
- transition duration 包含 `0.26s`；
- 动画结束后内联 height 被清理。

若实现成本需要先做较小改动，也可以使用短间隔 `expect.poll`，但每次 poll 必须在**同一次 `locator.evaluate`** 中同时读取 class、rectHeight 和 transitionDuration，并且只有全部条件同时满足才保存样本。不能先在 Node 侧等待 class 再读取样式。

### 5.3 保留原始值和诊断信息

在任何数值断言前先执行 `Number.isFinite`，失败消息应输出：

- 原始 computed height；
- inline height；
- rect height 与 scrollHeight；
- class 历史；
- transition duration；
- 样本时间戳。

这样未来若是产品 motion 回归，报告能够区分“未进入 active”“进入后没有像素高度”“transition 配置丢失”和“采样发生在清理后”。

### 5.4 补充静态合同，防止脆弱读取回归

在 `tests/test_e2e_stability_contracts.py` 的工作区动效合同中增加：

- measured-height 用例不得出现 `Number.parseFloat(style.height)`；
- 必须使用 `getBoundingClientRect().height` 或等价真实几何值；
- 必须在点击前安装 recorder，或在单次 evaluate 内同时检查 active class 和高度；
- 必须检查 `Number.isFinite`；
- 不得通过 `waitForTimeout`、全局 timeout、retry 或删除断言规避问题；
- 四个工作区参数化用例仍保持独立，不能重新合并。

### 5.5 不修改产品动画，除非新证据证明产品缺陷

当前 `App.tsx` 已使用矩形高度和 scrollHeight，`index.css` 的 210/260ms 也符合设计。修复应优先局限于测试 recorder、断言和合同测试。只有修复后的帧记录显示：active 期间产品节点从未获得有限高度、transition 没有运行或快速反转留下残余样式，才应另建产品代码问题，不能基于本次 `NaN` 直接修改业务动画。

## 6. 禁止采用的表面修复

- 仅把 `parseFloat(style.height)` 换成 `getBoundingClientRect().height`，但仍在 class 断言之后另起一次非原子读取；
- 删除高度范围、transition-duration、aria-expanded 或清理状态断言；
- 给该测试增加 retry；
- 增大全局测试 timeout；
- 使用固定 `waitForTimeout` 猜测动画已经开始或结束；
- 把四个工作区场景重新合并成单一长测试；
- 为通过测试而缩短、关闭或删除产品动画；
- 把 `NaN` 转成 0 后继续断言。

## 7. 潜在影响与风险

1. **recorder 泄漏**：未断开 observer/rAF 会增加后续测试 CPU 占用并制造新的并发不稳定。
2. **样本数量失控**：只应在 enter/leave active 期间逐帧采集，并设置上限，避免长时间页面产生大量数据。
3. **假通过**：只断言最终高度 0 无法证明动画过程存在；必须把 active class、几何高度和过渡配置绑定到同一样本。
4. **过度严格**：不同浏览器帧率下不应要求某个精确中间像素值；应验证有限值、范围、方向和 transition 配置。
5. **快速反转**：recorder 应允许动画从当前进度反向开始，不能假设每次都从完整自然高度开始。
6. **reduced motion**：降低动画设置的用例应继续验证没有残余 active class，但不能与普通 210/260ms 采样混为一组断言。
7. **生产影响**：建议修改仅涉及 E2E 与合同测试，不应改变业务菜单、路由、权限或视觉动效。

### 8.3 完整并发回归

使用固定 Playwright 1.59.1 Ubuntu 镜像、4 workers、无 retry 连续执行两轮全量 E2E。要求：

- 两轮均全部通过；
- 相关动效用例不出现 `NaN`；
- 四个工作区场景继续独立通过；
- 快速反转、菜单高亮、reduced-motion 用例继续通过；
- 控制台和 page error 门禁保持为零；
- 保存 `results.json`、`console.log`、截图/trace（若失败）和资源记录。

### 8.4 验收成功判据

只有在“同帧 active + 有限几何高度 + 正确过渡时长”得到真实样本、相关断言未被弱化、导航重复 5 轮和全量两轮都绿色时，才能关闭本问题并将 `INTERACTION-014` 从“不通过”更新为通过。

## 9. 建议结论

该问题应作为独立的 E2E 动效观测缺陷修复。首选方案是在触发动画前安装带清理机制的帧 recorder，把 class、几何高度和 transition 配置绑定到同一个浏览器帧中验证。当前没有证据要求修改产品动画；应避免用最终高度 0、重试或延长 timeout 获得假绿色。
