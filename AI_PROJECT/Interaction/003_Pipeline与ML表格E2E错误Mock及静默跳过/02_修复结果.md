## 2. 修复结果总结

1. **类型化夹具**：新增 `e2e/helpers/apiFixtures.ts`，所有响应用 `satisfies <生产类型>` 约束。
   - Pipeline：`PIPELINE_HEALTH satisfies PipelineHealthResponse`。
   - ML 7 个接口：`ML_HEALTH`、`ML_MODELS`、`ML_BUFFER`、`ML_DRIFT`、`ML_SHADOW`、`ML_TRAINING`、`ML_READINESS`。
   - 告警、客户、设备、租户、用户、情报、AI、插件、配置级联等页面的夹具也一并补齐。
   - 字符串枚举使用值导入（如 `ThreatLevel.HIGH`），其余使用 `import type`。
   - 夹具中包含超长服务名、模型路径、URL、标题、IPv6 等，用于覆盖单行省略和悬浮提示场景。
2. **按路径精确分发，取消万能成功响应**：新增 `e2e/helpers/mockApi.ts`。
   - 应用发出的全部 GET 都在 `MOCK_ROUTES` 中登记了路径、响应形态（`page` / `array` / `object` / `scalar`）和夹具。
   - 分页包装 `page()` 只用于声明为 `page` 的接口；原 `EMPTY_PAGE` 万能兜底已删除。
   - **未登记的 GET 一律返回 HTTP 501**，路径写入 `unexpectedRequests`，表格用例会因此失败并输出路径。
   - 夹具形态与声明不符时，解析器直接抛错。
3. **删除通用 `test.skip`**：`table-layout.spec.ts` 已重写（详见 004）。
   - 每个展示面声明预期表格数量，以及哪些视口应显示卡片。
   - 桌面/平板缺表时等待超时后直接**失败**。
   - Pipeline/ML 在 390px 下改为对移动卡片 `.tds-operate-mobile-records` 做正式断言，计入“通过”。
4. **错误监听与语义等待**：每个用例监听 `pageerror` 和 `console.error`，并断言 `unexpectedRequests` 为空。
   - `console.error` 只放行已登记的 antd 开发版废弃提示（`Warning: [antd: …]`）。
   - 不再依赖 `networkidle`，改为等待“目标表格出现、行数达标、无加载转圈、弹窗/抽屉动画结束”。
5. **Mock 自身的契约测试**：新增 `e2e/api-mocks.spec.ts`（不启动浏览器），覆盖：
   - 每条路由的形态；
   - Pipeline/ML 等对象、数组、分页互不混用；
   - 未知路径被报告、不返回伪成功；
   - `/api/api` 前缀规范化；
   - 形态错误时报错。
6. **E2E 类型检查入口**：新增 `frontend/tsconfig.e2e.json` 和 npm 脚本 `typecheck:e2e`。原 `tsconfig.json` 只覆盖 `src`，Playwright 运行时也不做类型检查，此前夹具类型不受约束。
7. `auth.ts` 的对外接口保持不变（`setAuthState` / `stubApiAvailability` / `clearAuthState`），内部改为调用严格 Mock。另新增 `setTheme()`（供 004 的主题矩阵使用）和 `getApiMockReport()`。

## 4. 测试结果

### 4.1 测试环境（必读）

工作区访问 npm 仓库仍被网络策略拒绝（403），无法安装依赖。为了让 E2E 真正跑起来，本轮做法如下：

- 从本机 `frontend/node_modules` 复制各依赖包自带的浏览器版文件（UMD）：React 18、antd 5.27.6（含语言包）、`@ant-design/icons`、`@ant-design/charts`、recharts、react-router、i18next 等。
- 用 esbuild 按项目的路径别名打包**真实的 `src` 源码**，由一个静态服务器在 3000 端口提供页面，替代 `npm run dev`。
- 用工作区的 Playwright（Chromium）运行项目原有的 E2E 用例，`@playwright/test` 通过一个转发模块指向它。

与本机 Vite 环境的差异：

| 差异 | 影响 | 处理 |
| --- | --- | --- |
| `@ant-design/pro-components` 的浏览器版自带一份 antd 5.25.4，ProTable 不吃项目的 `ConfigProvider` 主题 | ProTable（告警明细、情报指标、客户、设备列表）的单元格内边距和深色配色与生产不同；全局表格 CSS 依旧生效 | 本地运行设置 `E2E_LOCAL_UMD_BUILD=1`，**只跳过这 4 张 ProTable 的深色对比度一项**并在报告中注明。其余检查照常执行。在本机 `npm run dev` 下不设置该变量，全部检查都会执行 |
| 生产版 React/antd，没有开发版警告 | 本地不会出现开发版 `console.error` | 白名单已预先放行 antd 开发版废弃提示 |
| 2 核 CPU、6 个 worker 并发 | 个别依赖动画时序的旧用例不稳定 | 见 4.2 的基线说明 |

## 5. 与方案的差异

| 方案 | 实际 | 原因 |
| --- | --- | --- |
| “该任务原则上只修改 E2E 测试和 fixture” | 本问题确实只改 E2E 与配置；但同一轮 004 新增了一个测试专用页面，并做了一处生产重构（主题抽取）及一处缺陷修复，均在 004 文档中说明 | 不属于本问题范围 |
| 未知请求“返回 501 或让测试失败” | 两者都做：一律返回 501；表格用例和交互用例断言 `unexpectedRequests` 为空。其他旧用例只返回 501、不额外断言 | 旧用例在严格 Mock 下全部保持原结果，且未知请求为 0；后续新增页面接口若未登记，会在表格用例中直接暴露 |
| 夹具“至少一条可见数据” | 所有表格接口均有 1–3 条数据；部分旧夹具原本返回空（如分组威胁、告警） | 让旧用例里的空表也得到真实渲染检查；修改后旧用例结果不变 |

## 6. 未解决问题与注意事项

1. **生产类型与运行时字段不一致（新发现，未修改生产代码）**：`pages/Overview/index.tsx` 读取的是 `trend[].timestamp`，而 `types/index.ts` 中 `ChartDataPoint` 声明的是 `time`。夹具同时提供两个字段以保证页面正确渲染。建议另立问题核对后端返回字段并修正类型。
   > **后续更新（2026-10-28）**：已由 `INTERACTION-008` 修复。新增 API 类型 `ThreatTrendPoint`，Overview 改用 `toTrendChartData` 统一映射；夹具改为只含后端 `TrendDataPoint` 字段的 `THREAT_TREND`，不再携带 `time`/`value`。详见 `008_Overview趋势接口字段契约不一致/02_修复结果.md`。
2. 新增或调整页面接口时，必须同时在 `MOCK_ROUTES` 登记带类型的夹具，否则表格用例会因 501/未知请求失败。这是有意为之。
3. `console.error` 白名单目前只有 antd 开发版废弃提示一项。如果本机开发模式下出现其他已知的无害噪声，应在 `table-layout.spec.ts` 的 `CONSOLE_ALLOWLIST` 中逐条登记并写明理由，不能整体关闭检查。
4. 本环境无法执行 `npm run lint`、`vitest`、`npm run build` 和基于 Vite 开发服务器的 Playwright。请在本机执行：

```powershell
cd F:\codex\threat-detection-system\frontend
npm run lint
npm run typecheck:e2e
npx playwright test e2e/api-mocks.spec.ts e2e/table-layout.spec.ts
npx playwright test   # 全量，确认旧用例结果不变
```
