# 3.1.35 告警工作流、情报记录与 AI 配置体验修复

日期：2026-10-23

## 根因

- 告警状态同时承载系统动作和人员进度，指派只保存自由文本且不更新状态；前端又用 `ESCALATED` 状态判断提级，但后端实际只改层级字段。
- 提级服务先改一个告警实体，再通过状态更新重新加载另一个实体保存，导致层级和原因可能丢失。
- 告警列表没有展示责任闭环字段，完成处置时实际处理人由操作人员自由输入，难以审计。
- 情报列表分页查询没有固定排序；更新目击时间后数据库返回顺序可能变化，造成当前行“消失”的假象。前端 IOC 枚举也与后端定义不一致。
- API Key 按安全要求不回显，但连接测试只使用页面提交值，没有在空值时读取已保存密钥。
- 系统配置按数据库默认顺序返回，页面直接按数组渲染；保存、刷新或查询计划变化会导致字段位置漂移。

## 实现

### 告警

- 新增 `IN_PROGRESS` 工作状态，指派启用用户后自动进入处理中；已处置和已归档记录不会被指派操作重新打开。
- 完成处置由当前登录账号写入实际处理人，并持久化处置结论和完成时间。
- 提级与取消提级改由告警服务在事务中直接保存层级和原因；操作按钮以实际层级判断，不再依赖未使用的状态值。
- 统计响应补齐已处置和已提级计数；自动提级时间阈值按配置定义的秒数计算。
- 页面状态筛选只呈现四类人员工作状态；主表增加责任人并收敛列宽、单行省略，详情抽屉承载完整描述、层级、原因和处置审计信息。
- 分组子表同样提供详情入口；行操作使用查看、完成处置、指派责任人、提级/取消提级的清晰文案和无障碍名称。

### 威胁情报

- 指标接口支持真实 `iocType`、`severity` 筛选，并默认按 `id DESC` 稳定分页。
- 再次出现接口返回更新后的指标；出现次数加一、最后发现时间更新，记录不删除。
- 前端 IOC 枚举改为 `IP_V4`、`IP_V6`、`CIDR`、`DOMAIN`、`FILE_HASH`，与后端一致。

### AI 与配置

- LLM 连接测试对 API Key、Base URL 和模型分别执行“本次输入优先、已保存配置兜底”；密钥从数据库读取后解密，只传给内部验证服务。
- secret 响应仍只返回掩码和 `hasValue`，不回传明文。
- 系统配置查询按 ID、键名稳定排序；LLM、情报密钥、通用情报和插件配置再按前端业务顺序排列。

### 文案与术语

- 删除会话到期提示中的内部清理说明，保留重新登录提示。
- 用户界面统一“可疑来源、观察周期、责任人、实际处理人、处置层级、提级处理、处置结论、再次出现、配置归属”。
- 后端字段名和 API 路径保持不变，保障旧客户端及服务间契约。

- 新增告警指派/提级、情报筛选/再次出现、保存密钥复用和配置稳定排序测试。

## 安全与兼容边界

- 不回显 LLM API Key，不打印解密值；真实第三方连接仍由部署环境网络和客户凭据决定。
- 不删除历史告警状态或情报数据，不修改既有 API 路由、请求字段、权限角色及安装部署流程。
- 本轮不部署或覆盖 `192.168.100.8` 运行节点；`192.168.100.9` 仅用于测试、构建和发布归档。
