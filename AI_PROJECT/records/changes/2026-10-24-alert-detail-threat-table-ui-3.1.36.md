# 3.1.36 告警详情与威胁列表界面一致性修复

日期：2026-10-24

## 根因

- 告警责任人列把 ProTable `render` 的首个参数当作原始字段；该参数在省略显示场景下是 React 节点，执行 `String` 后得到 `[object Object]`。
- bordered Descriptions 只有全局颜色和字体规则，没有标签宽度、不换行和值区域长文本策略，较长中文标签会拆行。
- Ant Design TextArea 的字数统计绝对定位在输入框底部之外，Modal 正文没有预留对应空间。
- 威胁列表同时存在默认左对齐、数值右对齐和状态居中，选择列、展开列及排序表头也没有统一规则。

## 实现

- 告警责任人、MAC、评分和处置层级从告警记录读取真实字段；新增 `formatAlertOwner` 防止异常非字符串值泄露为对象文本。
- 增加局部 `tds-detail-descriptions` 规则；告警详情使用响应式标签宽度，值区域可处理长内容。
- 完成处置和提级处理文本域增加计数安全区，并为文本域及责任人选择器补充可访问名称。
- 威胁明细、分组和展开子表全部显式 `align: center`；页面级表格样式覆盖选择/展开辅助列和排序器布局。
- 同类修复覆盖客户/设备详情、威胁详情、威胁情报查询结果和基础配置，未修改接口、权限或业务流程。

## 本地验证

- ESLint 以 `--max-warnings 0` 通过。
- TypeScript `tsc --noEmit` 通过。
- 新增责任人显示值单元测试；完整前端测试共 45 项通过。
- Vite 生产构建通过；仅保留既有 CJS API 弃用与大 chunk 非阻断提示。
