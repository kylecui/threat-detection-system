# 3.1.17 控制面契约与响应性整改

## 背景

3.1.16 全新安装后发现四类控制面问题：未选择客户时威胁列表请求返回 400、空库 SMTP 页面返回 404、Customer Management 冷请求被网关过早熔断，以及 ML 页面因同步读取大量训练特征而长时间等待。

## 修改

- 威胁明细、分组和租户查询统一使用 `page`/`size`；客户作用域未就绪时不发送客户级查询，只加载当前可见视图。
- SMTP 默认配置 API 将空库视为 `configured=false` 的正常状态；默认配置支持幂等创建/更新，更新时密码留空表示保留，所有响应均不返回密码。
- Customer Management 网关超时预算明确为 5 秒，增加慢调用熔断参数、request ID/根因日志和安装期真实分页查询预热。
- ML 数据就绪检查改为数据库单次聚合统计，在工作线程执行并设置 SQL/协程超时和 30 秒缓存；漂移计算也移出 API 事件循环。
- ML 页面核心状态优先显示，训练数据与漂移指标独立加载；轮询串行、页签隐藏时暂停，避免重复请求拖慢页面。
- 新增四类问题的轻量回归契约，并保留 3.1.16 的空业务库、首次管理员、高吞吐接入、业务 readiness、失败回滚和 purge 能力。
- 测试 profile 禁用仅依赖外部数据库的健康贡献项，使网关独立测试检查网关本身；生产健康检查保持不变。

## 兼容性

- 不改变客户端接入协议、Kafka 主题、威胁评估数据结构或公开端口。
- 全新数据卷自动创建客户/等级聚合索引；已有数据卷仍需后续正式迁移机制补建索引。
- SMTP 密码只允许写入，不再通过 API 回显；已有配置更新时可留空密码。
