# 浮层滚动稳定性与 Flink 单次安装回退

日期：2026-10-21  
版本：3.1.32

## 问题一：滚动后打开弹窗导致侧边栏位移

### 根因

业务页面原本通过浏览器 `body` 滚动，侧边栏和顶部栏又使用 `position: sticky`。Ant Design Modal/Drawer 打开时会对 `body` 应用滚动锁定并补偿滚动条宽度，使 sticky 元素的包含块和视口几何关系在浮层开启瞬间发生变化。因此异常并非某个 LLM 弹窗自身的定位错误，而是应用外壳与浮层滚动锁定共用 `body` 造成的系统性问题；同一布局内所有 Modal/Drawer 都可能复现。

### 修复

- `.tds-shell` 固定为视口高度并隐藏外层溢出。
- `.tds-main-layout` 限制最小高度并隐藏外层滚动。
- `.tds-content` 成为唯一业务滚动容器，使用纵向 `auto`、横向隐藏和稳定滚动条槽位。
- 侧边栏与顶部栏改为应用外壳内的稳定相对定位；在线状态和折叠控制仍固定在侧边栏底部。
- 去掉侧栏子容器对收缩按钮高度的重复扣减；Sider 的底部内边距单独负责预留 48px 按钮空间，使在线状态与收缩按钮保持 0–8px 的紧邻关系。
- 不修改 Modal/Drawer 业务组件、路由、表单或接口，修复对全部页面统一生效。

### 回归验证

- 1280×640 视口下滚动 AI 配置页主内容后打开“添加 LLM 供应商”。
- 浮层打开前后侧边栏底部状态、折叠按钮、顶部栏矩形位置和主内容 `scrollTop` 保持一致。
- 浏览器 `window.scrollY` 始终为 0，浮层打开时 `body` 可继续由 Ant Design 安全锁定。

## 问题二：Flink 镜像导致安装必须运行两次

### 根因

目标机配置的 Docker Hub 镜像加速器能够拉取多数镜像，但对 `flink:1.18.1-scala_2.12-java17` 的两个大层长期停滞或返回错误。安装器此前只重试同一个官方标签；操作员手工拉取 DaoCloud 完整地址后，本地仍只有 DaoCloud 仓库标签，Compose 所需的官方标签不一定可直接命中，导致流程依赖人工介入或再次执行。

### 修复

- 官方标签每轮失败后自动尝试 `docker.m.daocloud.io/library/flink:1.18.1-scala_2.12-java17`。
- 回退镜像必须包含固定 RepoDigest `sha256:44af270538aa97418be63d0f42b2f4400d12c5e41e58813f8b4b85d52fe27f5d`。
- 摘要通过后自动执行本地重新标记，使 Compose 继续使用原有 `flink:1.18.1-scala_2.12-java17`，不改 Compose 契约。
- 已存在且摘要正确的回退标签会直接复用；摘要不一致时拒绝使用。
- 全部动作仍发生在停止旧服务和同步安装目录之前，失败不会形成半安装状态。

## 验收标准

- 官方标签模拟失败、DaoCloud 标签模拟成功时，单次 `pull_container_image` 调用返回成功并产生官方标签。
- 拉取顺序必须是官方标签在前、DaoCloud 回退在后。
- 不允许跳过摘要校验或直接信任同名标签。
- 原有安装、升级、回滚、数据卷和 Compose 配置保持不变。

## 远程干净构建补充

在 `192.168.100.9` 使用 Node 22 容器执行全新 `npm ci` 时，发现原锁文件缺少部分间接依赖和 Linux 平台可选依赖；本机已有 `node_modules` 会掩盖该问题。已在无依赖目录的 Linux 环境重新生成 `frontend/package-lock.json`，随后按 `npm ci → npm test → npm run build` 完整通过。

发布契约中另有三项断言把引号和换行格式写死，Prettier 格式化后会在功能未变时误报；已改为等价的语义正则。空库初始化测试的迁移账本预期也从 43–45 同步为实际发布包含的 43–47。以上只修复验证基线，不改变客户、设备或数据库运行逻辑。
