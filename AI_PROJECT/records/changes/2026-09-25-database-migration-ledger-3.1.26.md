# 3.1.26 数据库迁移账本整改

## 发现的问题

- 全新安装时 PostgreSQL 会执行初始化目录中的 43–45 号 SQL。
- 安装器等待数据库就绪后又无条件执行相同 SQL，输出字段和索引已存在的 NOTICE。
- NOTICE 虽不是错误，但会让操作员误认为 purge 没有清除数据库。
- 已有数据卷升级确实需要显式迁移，因此不能简单删除升级阶段。

## 原因

- 初始化脚本和升级脚本共用同一批 SQL，却没有持久化的迁移完成记录。
- 安装器无法区分“刚由空卷初始化完成”和“保留旧数据、需要升级”两种数据库状态。

## 修改

- 新增 `tds_schema_migrations` 迁移账本，并作为 `00` 号初始化脚本最先执行。
- 43–45 号迁移成功后写入自身文件名；重复登记使用主键冲突忽略。
- 安装器读取账本，已登记脚本直接跳过，只执行未登记脚本。
- 历史数据库没有账本时自动创建；首次纳管时收敛幂等 DDL 的 NOTICE，但保持 `ON_ERROR_STOP=1`。
- 每个未登记迁移执行后重新读取账本，未登记成功则立即判定安装失败。

## purge 边界

- 迁移账本、字段、索引和业务数据都位于 PostgreSQL 数据卷。
- `--purge` 删除项目卷，因此这些状态全部删除；新装后由初始化链重新创建。
- `--uninstall` 明确保留卷和迁移账本，重新安装时不会重复迁移。

## 设备管理弹窗

- 设备管理抽屉宽度从 1200px 提升为桌面最大 1480px。
- 序列号、描述、主机数、各状态、最后数据时间、创建时间和操作列使用明确列宽。
- 表头、状态标签和时间值保持单行；小屏幕保留横向滚动，不通过压缩列宽造成逐字换行。

## 设备数据状态一致性

- 原实现的设备管理抽屉只在进入时请求一次，所有设备状态都会停留在旧快照；弹窗又仅刷新下方的原始攻击日志，顶部继续引用旧设备对象，因此会出现下方已有日志、上方仍显示“暂无攻击日志”。
- 抽屉打开期间每 15 秒静默刷新设备列表和配额，不显示整表加载动画；工具栏同时提供手动刷新按钮。
- 打开数据状态弹窗和日志翻页时，现并行请求最新设备详情及原始事件；详情接口继续作为权威汇总来源。
- 当原始事件已经返回而汇总仍短暂滞后时，以本页事件对最后攻击时间、最后接收时间、24 小时数量下限、数据活跃度和分析链路做一致性校正。
- 校正后的设备同时回写抽屉列表；弹窗第一页每 15 秒静默刷新，关闭时递增请求代次以丢弃过期响应。

## 威胁总览端口分布

- 原柱状图为每个端口绘制等宽实心柱，并将 `Port xxxxx` 标签旋转显示；计数接近时视觉上形成整片蓝色栅栏，标签也难以扫读。
- 新增 `frontend/src/components/ui/AreaChart.tsx`，采用 Recharts 的响应式容器、渐变填充、整数纵轴、节点和自定义 Tooltip。
- 总览只在横轴展示精简端口号；Tooltip 明确显示“端口”和“攻击次数”，保留 Top 15 API 数据及原有时间范围筛选。
- 图表颜色、网格、坐标轴和浮层使用 CSS 主题变量，同时支持亮色和暗色模式；没有引入与现有 Ant Design 冲突的 Tailwind/shadcn 样式层。
