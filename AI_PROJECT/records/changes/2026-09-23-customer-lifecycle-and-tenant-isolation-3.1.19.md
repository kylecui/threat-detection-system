# 3.1.19 客户生命周期与租户隔离整改

## 发现的问题

- 客户管理页面为空时，重新创建历史客户 ID 返回 409；实际记录只是被软删除为 `INACTIVE` 后从列表过滤，操作员既看不到也无法恢复。
- 客户创建按钮可重复触发，同一次 409 会被全局拦截器和页面重复提示。
- Tenant Admin/Customer User 的路径客户 ID和查询参数作用域未完全收敛，旧 JWT 在账户、租户或客户停用后仍可能继续使用。
- 客户停用没有贯穿设备绑定、攻击日志和心跳入口；永久删除也没有系统检查跨服务关联数据。
- 前端套餐枚举、客户 ID 长度和后端不一致；客户 ID 在编辑页面仍可修改但后端不会真正更新。
- 客户和租户弹窗使用固定默认密码自动创建管理员，跨服务失败会留下半完成状态。

## 根因

- “软删除”和“归档”没有统一业务语义，列表查询直接排除了 `INACTIVE`，但数据库唯一约束仍保留记录。
- 网关规则只覆盖部分写接口，没有同时校验路径资源、两种查询参数命名和数据库实时生命周期状态。
- 客户状态只存在 Customer Management，未成为认证、设备绑定和 Data Ingestion 的共同前置条件。
- 前端沿用旧枚举及非原子的“创建客户后再创建默认用户”流程，且请求错误由两层同时提示。

## 修改

- 管理列表和搜索保留归档客户；编辑状态可显式恢复，作用域选择器仍只列出非归档客户。
- 永久删除要求 `SUPER_ADMIN`、先归档且无关联数据；冲突响应返回依赖表及数量。
- API Gateway 每次请求读取实时 AuthUser，并验证 Tenant/Customer 为 `ACTIVE`；路径与查询参数均覆盖为认证主体的权威作用域。
- 新设备绑定、V1 攻击日志和心跳仅接受活动客户；接入侧加入 5 秒客户状态缓存，防止百万级事件逐条查库。
- 客户 ID 统一为 50 字符、创建后只读；套餐统一为 `FREE/BASIC/PROFESSIONAL/ENTERPRISE`。
- 客户创建提交期间禁用确认按钮；本地处理的错误关闭全局重复提示，并展示后端冲突原因。
- 移除客户/租户弹窗的固定密码自动建号；用户管理页统一校验 12–128 位且至少包含字母和数字。

## 兼容边界

- `DELETE /api/v1/customers/{id}` 仍执行可恢复归档，不删除历史业务数据。
- 已归档 ID 不允许复用；如确需物理删除，必须清理依赖后由超级管理员调用硬删除接口。
- Data Ingestion 的停用状态最长约 5 秒生效，以换取高吞吐事件链不对 PostgreSQL 逐条查询。
- 本次不部署 `192.168.100.8`，只在 `192.168.100.9` 完成构建、测试和发布包生成。
