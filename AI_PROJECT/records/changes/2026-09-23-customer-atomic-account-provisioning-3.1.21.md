# 3.1.21 客户创建与可选账号原子化整改

## 现场问题

- 客户管理列表为空时创建客户返回 `500 Internal Server Error`。
- 运行日志表明真实业务错误是 `Select a tenant before creating a customer`，即调用时没有有效租户。
- Customer Management 的通用异常处理器捕获了 `ResponseStatusException`，把原本明确的 400/403 统一改写成 500。
- 3.1.19 为消除固定 `changeme123` 和跨服务半成功而删除了弹窗自动建号，但缺少安全、可选且原子化的替代流程。

## 修改内容

1. 客户创建按钮在未选择租户时禁用，并显示先选择租户的提示；提交函数保留二次保护。
2. 后端异常处理器单独处理 `ResponseStatusException`，保留原始 HTTP 状态和原因。
3. 客户 ID 契约统一为 `^[A-Za-z0-9][A-Za-z0-9_-]*$`，最长 50 位。
4. 创建弹窗增加“同时创建客户管理员账号”复选项，默认开启但允许关闭。
5. 自动账号固定为 `<客户ID>-admin`；密码固定以 `<客户ID>@` 开头，并由浏览器 `crypto.getRandomValues` 生成高强度随机后缀。
6. 服务端重新校验账号关系和密码强度，使用 BCrypt 存储哈希，不信任前端校验。
7. 客户、账号和 `CUSTOMER_USER` 角色绑定由 Customer Management 在同一个数据库事务中完成，任一步失败时整体回滚。
8. 创建成功后只向当前操作员展示一次初始账号和密码；服务端日志只记录客户 ID 和账号，不记录密码。
9. 清理未使用的历史固定密码国际化文案，并补充服务与异常映射回归测试。

## 权限边界

现有 RBAC 只有 `SUPER_ADMIN`、`TENANT_ADMIN` 和 `CUSTOMER_USER`。本次自动创建的是绑定到具体客户和租户的 `CUSTOMER_USER`，用于该客户范围的数据访问，不会静默赋予租户管理或跨客户写权限。更高权限仍须在用户管理页由有权操作员显式分配。

## 兼容性

- 不勾选自动建号时，客户创建行为与 3.1.20 一致。
- 允许 ID 中使用历史已支持的 `-` 和 `_`，避免破坏已有命名规范。
- 不修改数据接入、Kafka、MQTT、Syslog、设备绑定和客户归档流程。
