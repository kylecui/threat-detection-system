# 威胁情报与 Web 回归修复记录（2026-10-21）

## 修复范围

- 修复威胁情报订阅源表格只有 ID、类型和开关，名称、URL、最后拉取时间为空的问题。
- 修复订阅源数、活跃订阅源数和 IP 查询详情长期显示为零或 `-` 的接口契约问题。
- 修复只启用内部 `internal` 源时，页面误认为外部情报源已启用的问题。
- 修复轮询成功后只刷新订阅源、不刷新指标列表和统计卡片的问题。
- 修复 VirusTotal 订阅源使用 `VIRUSTOTAL_API_KEY`，而系统配置和 TIRE 实际使用 `VT_API_KEY` 的不一致。
- 修复威胁列表单条、批量删除按钮调用不存在的后端端点而返回 404 的问题。
- 修复 ProTable 横向筛选表单标签未与输入控件垂直居中的同类问题。
- 统一异步按钮的加载、禁用和重复提交保护，并取消会导致弹层锚点位移的按钮按压缩放。

按本次任务约定，客户设备连接平台 `9080/tcp` 的网络和部署问题不在本批修改范围内。

## 根因

威胁情报后端返回 `feedName`、`feedUrl`、`lastPollAt`、`lastPollStatus`，前端却读取 `name`、`url`、`lastPolledAt` 和不存在的 `status`。统计响应未包含前端卡片读取的订阅源计数；IP 查询后端返回置信度、严重程度、情报权重、来源和 TIRE 字段，前端仍按旧版 `indicators/reputation/categories` 结构展示。上述字段在 TypeScript 中被错误声明，因此编译无法发现运行时空白。

横向筛选表单的问题来自全局 `.ant-form-item-label > label { height: auto; }` 覆盖 Ant Design 横向布局的控件高度；触发器位移则来自全局按钮 `:active` 使用 `transform: scale(0.96)`，弹窗/下拉在按下阶段计算锚点时会得到变化后的几何位置。

威胁列表前端已暴露删除入口，但 `AssessmentController` 没有对应 `DELETE /api/v1/assessment/{id}` 和 `POST /api/v1/assessment/batch-delete` 端点。

## 实施内容

1. 前后端 `ThreatFeed`、统计和 IP 查询字段统一；订阅源表格增加真实名称、地址、密钥配置项、拉取状态和错误提示，并按视口隐藏次要列，避免强制横向滚动。
2. 统计加载失败显示可重试错误，不再把接口失败伪装成真实零值；空 IP 禁止提交。
3. 拉取、启停、目击、删除、设备同步和取消升级等异步操作增加进行中反馈与重复提交保护。拉取完成同步刷新订阅源、指标表和统计卡片。
4. 数据库迁移 `48-threat-intel-feed-contract.sql` 为旧安装补齐缺失的内置外部源，并只将 VirusTotal 密钥配置项校正为 `VT_API_KEY`，不覆盖管理员已有的启用状态、URL 或轮询周期。
5. 增加范围安全的单条/批量威胁删除：租户只能删除本租户客户数据，显式客户范围只能删除该客户数据；批量请求先完成全部校验，再一次提交，避免部分删除。
6. 横向 ProTable 标签恢复 38px 对齐；竖向表单继续使用自然高度。按钮按压反馈改为边框和背景颜色，不再缩放触发器。

## 操作流程

1. 在“配置 → 集成配置”保存 `ABUSEIPDB_API_KEY` 等密钥。
2. 进入“威胁运营 → 威胁情报 → 订阅源管理”。
3. 启用与密钥对应的外部订阅源；`internal` 仅表示内部来源。
4. 点击“拉取”，观察状态、指标数量和最后拉取时间。
5. 在“威胁指标”页查看导入结果，或在 IP 查询区执行按需信誉查询。
