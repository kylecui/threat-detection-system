# 告警工作流、情报与 AI 配置修复说明

版本：3.1.35  
日期：2026-10-23

## 1. 告警中心

### 1.1 页面现在表达什么

面向操作人员的处置状态收敛为四类：

| 状态 | 含义 |
| --- | --- |
| 待处置 | 告警已进入平台，尚未明确责任人或开始处理 |
| 处理中 | 已指派责任人，正在研判和处置 |
| 已处置 | 已填写处置结论并记录实际处理人和完成时间 |
| 已归档 | 已结束日常处置，作为历史记录保留 |

`已合并`、`系统处理中`、`通知已发送` 等值仍保留在后端兼容历史数据和内部处理，但不再混入日常状态筛选，避免把系统动作误当成人员工作进度。

### 1.2 责任人、实际处理人和提级处理

- **责任人**：当前负责跟进该告警的启用账号。指派后，未结束的告警自动进入“处理中”。
- **实际处理人**：点击“完成处置”的当前登录账号，由系统自动记录，不再让操作人员自由填写姓名。
- **处置层级**：表示当前需要哪一级人员或团队关注。常规处理为基础层级，需要更多权限或经验时使用“提级处理”。
- **提级原因**：说明为什么需要提高处置层级。提级不替代“待处置/处理中/已处置”的工作状态，两者分别表达进度和处理难度。

列表只展示研判所需的核心字段，并保持标题、责任人、时间和操作单行显示。完整描述、责任人、处置层级、提级原因、实际处理人、完成时间和处置结论统一在“告警详情”中查看，避免为了显示所有内容把表格挤乱。

### 1.3 本次根因修复

- 原提级流程先修改一个实体，随后又通过另一次状态更新重新读取并保存新实体，导致处置层级和提级原因没有可靠落库。现改为由告警服务在同一事务中直接保存提级字段。
- 原指派只保存一段自由文本，不改变处置进度。现从启用账号中选择责任人，并同步进入“处理中”。
- 原前端用 `ESCALATED` 状态判断是否已经提级，但后端实际只更新层级字段，造成按钮状态错误。现统一以处置层级是否大于零判断。
- 原统计响应缺少已处置和已提级数量字段。现分别按工作状态和处置层级计算。

## 2. 威胁情报中的“再次出现”

“记录再次出现”表示操作人员确认这个 IOC（例如恶意 IP、域名或文件哈希）又在新的事件中出现。操作后：

1. 出现次数增加 1；
2. 最后发现时间更新为当前时间；
3. IOC 本身不会被删除，也不会变成另一条数据；
4. 后续研判可以据此判断它是偶发记录还是持续活跃的风险来源。

原页面在操作后重新请求一个没有固定排序的分页列表，数据库可能把刚更新的记录放到另一页，看起来像“整行消失”。现在列表默认按 ID 稳定倒序，后端返回更新后的记录，IOC 类型筛选也与真实枚举保持一致。

## 3. AI 配置保存与连接测试

API Key 保存后输入框保持为空是安全设计：服务端只返回“已配置”状态，不把密钥明文再次发给浏览器。本次修复的是后续测试流程：

- 输入了新密钥时，连接测试使用当前输入；
- 输入框为空但已保存密钥时，后端解密并使用已保存密钥；
- 没有保存且没有输入时，页面才提示先填写密钥；
- 密钥依然不会出现在页面响应、日志或测试结果中。

LLM 字段固定按“API Key、模型、Base URL”显示；情报密钥和插件配置同样采用确定顺序。后端按记录 ID/键名排序，前端再按业务顺序兜底，因此保存或刷新不会让名称与 URL 看起来互换位置。

## 4. 会话提示与术语

登录过期只提示“登录已过期，请重新登录”，不再显示“系统已清除上一次会话和数据范围选择”这类内部实现信息。实际的令牌与范围清理仍会执行，不改变安全行为。

本轮面向用户统一以下术语：

| 旧表达 | 新表达 | 原因 |
| --- | --- | --- |
| 攻击者 MAC / IP | 可疑来源 MAC / IP | 当前数据不一定已证明对方就是攻击者 |
| 检测窗口 | 观察周期 | 说明这是聚合观察跨度，不是扫描频率 |
| 分配给 | 责任人 / 指派责任人 | 明确对象是负责处理的账号 |
| 升级级别 / 升级告警 | 处置层级 / 提级处理 | 避免与软件升级、版本升级混淆 |
| 解决人 / 解决说明 | 实际处理人 / 处置结论 | 更符合安全运营处置语境 |
| 记录目击 | 记录再次出现 | 直接表达数据变化和业务含义 |
| 配置分配 | 设置客户配置 / 配置归属 | 明确是配置作用范围，不是人员任务 |

API 字段名和既有路由保持不变，避免破坏前后端及第三方调用兼容；术语调整只作用于显示文案、接口说明和新增文档。

## 5. 兼容性与验证边界

- 不删除历史告警状态、告警、IOC 或配置数据。
- 不更改既有 API 路径、权限角色、部署入口和后端接口主体字段。
- 加入待处置指派、已处置保护、提级保存/取消、情报筛选/再次出现和已保存 LLM 密钥测试的回归测试。
- 真实第三方 LLM 调用仍需要部署环境提供有效 API Key、Base URL、模型和可达网络；发布验证不会使用客户真实密钥产生外部费用。
